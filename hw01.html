0.0作業環境：怎麼在自己的電腦編譯

為什麼筆記裡寫 g++，我的電腦卻是 clang++？

g++（GNU）和 clang++（LLVM，Mac 上叫 AppleClang）是兩個不同廠牌的 C++ 編譯器，就像 Word 和 Pages 都能打開同一份文件。它們都實作同一份 C++ 標準，所以標準寫法的程式在兩邊編譯、執行的結果一樣；差別只在錯誤訊息的措辭和部分警告。課程網站是在 Linux 伺服器上建置的，那裡預設的是 g++；你的 Mac 在 VS Code 裡 CMake 實際呼叫的是 /usr/bin/clang++（AppleClang 17，從你專案的 build/CMakeCache.txt 可以看到）。在 Mac 的終端機輸入 g++ --version，會發現它其實也是 clang 的別名。作業說明也寫了「可使用 GCC、Clang 或 MSVC」。

① 類別與物件：設計圖與成品

類別（class）是你自己定義的一種型態，把「資料」和「處理這些資料的函數」包在一起。可以把它想成設計圖：「債券」這張設計圖寫著每張債券都有面額、年期，也會算第 t 年的現金流。物件（object）是照設計圖做出來的一張張實際的債券。同一張設計圖可以做出很多物件，彼此獨立。

C++
#include <iostream>

class Bond {                       // 設計圖：債券
public:
    double face = 1000;            // 面額
    int maturity = 3;              // 年期
    double payment(int t) const {  // 第 t 年年底拿到多少錢
        return t == maturity ? face : 0.0;
    }
};

int main() {
    Bond a;                        // 照設計圖做出物件 a
    Bond b;                        // 再做一個物件 b
    b.face = 500;                  // 改 b 不影響 a
    std::cout << a.payment(3) << " " << b.payment(3) << '\n';
}

1000 500
  • a.payment(3)：用「物件.函數」的寫法，讓物件 a 算自己的第 3 年現金流。
  • 函數後面的 const 表示「這個函數只讀資料、不會改物件」，作業的 payment(int) const、value() const 都是這個意思。

② 成員與 public／private：誰可以碰資料

寫在類別裡的變數叫成員變數（member variable），函數叫成員函數（member function）。public: 之後的成員外面可以直接用；private: 之後的只有類別自己的成員函數能用。把資料設成 private、只開放經過檢查的函數，叫封裝（encapsulation），好處是別人不能把面額改成負數。習慣上 private 成員的名字後面加底線，例如作業裡的 face_、rates_。

C++
#include <iostream>

class Bond {
public:
    double face() const { return face_; }   // 外面只能「讀」面額
private:
    double face_ = 1000;                     // 外面不能直接改
};

int main() {
    Bond b;
    std::cout << b.face() << '\n';
    // b.face_ = -5;   // 這行會編譯失敗：face_ 是 private
}

1000

③ 建構函數與解構函數：物件的出生與消失

建構函數（constructor）和類別同名、沒有回傳型態，在物件誕生時自動執行，負責設定初始值、檢查參數。解構函數（destructor）寫成 ~類別名()，在物件消失時自動執行，負責收拾（例如歸還記憶體）。區域變數在離開大括號時消失，而且後建立的先消失。

C++
#include <iostream>

class Bond {
public:
    Bond(double face) : face_(face) {        // 建構函數；冒號後面是「初始化列表」
        std::cout << "建立面額 " << face_ << " 的債券\n";
    }
    ~Bond() { std::cout << "面額 " << face_ << " 的債券消失\n"; }
private:
    double face_;
};

int main() {
    Bond a(1000);
    Bond b(500);
    std::cout << "main 快結束了\n";
}                                            // 離開時先消失 b，再消失 a

④ 繼承：父類別與子類別

債券有很多種：零息債、固定票息債、階梯票息債。它們都「是一種」債券，都有面額和年期，只是每年付的錢不同。繼承（inheritance）讓我們先寫一個共同的類別，再讓其他類別沿用它：

  • 被沿用的叫父類別，也叫基底類別（base class），這裡是 Bond。
  • 沿用別人的叫子類別，也叫衍生類別（derived class），這裡是 FixedRateBond。
  • 寫法是 class FixedRateBond : public Bond，讀作「FixedRateBond 公開繼承 Bond」。子類別自動擁有父類別的 public 成員，不用重寫。
C++
#include <iostream>

class Bond {                                         // 父類別（基底類別）
public:
    Bond(double face) : face_(face) { std::cout << "Bond 建構\n"; }
    double face() const { return face_; }
private:
    double face_;
};

class FixedRateBond : public Bond {                  // 子類別（衍生類別）
public:
    FixedRateBond(double face, double c) : Bond(face), coupon_(c) {   // 先交給父類別建構
        std::cout << "FixedRateBond 建構\n";
    }
    double coupon() const { return face() * coupon_; }   // 直接用繼承來的 face()
private:
    double coupon_;
};

int main() {
    FixedRateBond f(1000, 0.05);
    std::cout << "每年票息 " << f.coupon() << '\n';
}

  • 建立子類別物件時，先建構父類別的部分，再建構子類別的部分；消失時順序相反。這就是第一題輸出順序的來源。
  • : Bond(face) 是在子類別的初始化列表中呼叫父類別的建構函數。

（補充：一個類別也可以同時繼承好幾個父類別，叫多重繼承，例如 class C : public A, public B。這份作業用不到，只要知道有這回事。）

⑤ 覆寫：子類別換掉父類別的做法

零息債的 payment(t) 只有到期還本；固定票息債每年還要付票息。子類別寫一個名字、參數、const 都和父類別一模一樣的函數，換成自己的做法，叫覆寫（override）。子類別裡要用父類別原本的版本時，寫 Bond::payment(t)。

C++
#include <iostream>

class Bond {
public:
    virtual double payment(int t) const { return t == 3 ? 1000.0 : 0.0; }   // 先不管 virtual，下一段說明
};

class FixedRateBond : public Bond {
public:
    double payment(int t) const override {           // 覆寫：同名、同參數、同 const
        return 50.0 + Bond::payment(t);               // 票息 + 父類別的版本（到期還本）
    }
};

int main() {
    FixedRateBond f;
    for (int t = 1; t <= 3; ++t) std::cout << f.payment(t) << ' ';
    std::cout << '\n';
}

50 50 1050
  • 函數後面加 override，是請編譯器幫忙檢查「這真的有覆寫到父類別的函數」。少了 const 之類的差異，編譯器就會報錯——這就是第二題（4）。

⑥ 虛函數 virtual：透過父類別也能叫到子類別

實務上我們常把各種債券都當成「債券」來處理，例如一個函數只寫 const Bond& b，傳進來的可能是零息債，也可能是固定票息債。問題是：在這個函數裡呼叫 b.payment(t)，會用父類別的版本還是子類別的版本？

  • 父類別的函數沒有 virtual：一律用父類別版本（看宣告的型別）。
  • 父類別的函數有 virtual（虛函數，virtual function）：程式執行時會看物件實際是哪一種，呼叫那一種的版本。
C++
#include <iostream>

class Bond {
public:
    virtual ~Bond() = default;
    virtual double payment(int) const { return 0.0; }     // 虛函數
};

class FixedRateBond : public Bond {
public:
    double payment(int) const override { return 50.0; }
};

void show(const Bond& b) {                    // 只知道「這是一張債券」
    std::cout << b.payment(1) << '\n';
}

int main() {
    Bond zero;
    FixedRateBond fixed;
    show(zero);     // 0
    show(fixed);    // 50：雖然參數型別是 Bond，仍叫到子類別的版本
}

0
50

這就是第五題的核心：定價器只寫一個 npv(const Bond&)，不用知道是哪一種債券，各種債券的差異交給虛函數處理。

⑦ 指標與參考：不複製，只是指著它

  • 參考（reference）const Bond& r = fixed;：r 是 fixed 的另一個名字，沒有產生新物件。
  • 指標（pointer）Bond* p = &fixed;：p 存的是 fixed 在記憶體中的位址，用 p->payment(1) 透過指標呼叫。& 放在變數前面是「取位址」。
  • 兩者都不會複製物件，所以都能保留物件「真正是哪一種」，虛函數才會照子類別的版本執行。
C++
#include <iostream>

class Bond { public: virtual ~Bond() = default; virtual double value() const { return 100; } };
class FixedRateBond : public Bond { public: double value() const override { return 105; } };

int main() {
    FixedRateBond fixed;
    const Bond& r = fixed;      // 參考：fixed 的另一個名字
    const Bond* p = &fixed;     // 指標：存 fixed 的位址
    std::cout << r.value() << ' ' << p->value() << '\n';   // 都是 105
}

⑧ 靜態型別、動態型別與多型

同一個 p，有兩種「型別」：

  • 靜態型別（static type）：編譯器從宣告看到的型別。const Bond* p 的靜態型別是 Bond*，編譯時就決定。
  • 動態型別（dynamic type）：p 實際指向的物件是什麼，程式執行時才知道，這裡是 FixedRateBond。

一般函數依靜態型別決定呼叫哪個版本；虛函數依動態型別決定。「同一行程式碼，因為物件實際種類不同而做不同的事」叫多型（polymorphism）。第三題的表格，就是把每一行的靜態型別與動態型別分開寫。

編譯器能做到這件事，是因為每個有虛函數的類別都有一張「函數位址表」vtable，物件裡藏著一個指向那張表的指標 vptr；呼叫虛函數就是去查表。第一題的關鍵是：建構父類別的那一刻，vptr 還指著父類別的表。

⑨ 重載與遮蔽：同名函數的兩種情況

  • 重載（overload）：同一個類別裡，好幾個函數同名、參數不同，例如 payment() 和 payment(int)。呼叫時編譯器看你給的引數，挑出對得上的那個（這一步叫重載決議）。
  • 遮蔽（name hiding）：子類別只要宣告了一個和父類別同名的函數，父類別所有同名的函數都會被「遮住」，透過子類別找不到。原因是編譯器找名字（名稱查找）時，在子類別找到就停了，不會再往父類別找。
C++
#include <iostream>
class Bond {
public:
    virtual ~Bond() = default;
    virtual double payment(int t) const { return t == 3 ? 1000.0 : 0.0; }
    double payment() const { return payment(3); }          // 重載：同名不同參數
};
class FixedRateBond : public Bond {
public:
    double payment(int t) const override { return 50 + Bond::payment(t); }   // 遮蔽了父類別的 payment()
};
int main() {
    FixedRateBond f;
    std::cout << f.payment() << '\n';     // 編譯失敗：找不到沒有參數的 payment
}

⑩ 按值傳遞與物件切割

函數參數寫成 Bond b（沒有 & 也沒有 ）叫按值傳遞（pass by value）：呼叫時會複製出一個新的 Bond 物件。把子類別物件按值傳給父類別參數時，只有「父類別那一部分」被複製過去，子類別多出來的部分被切掉，這叫物件切割*（object slicing）。新物件從頭到尾就是一個 Bond，虛函數也只會叫到 Bond 的版本。

⑪ new、delete 與虛解構函數

一般的區域變數放在堆疊（stack），離開大括號就自動消失。用 new 要的記憶體放在堆積（heap），不會自動消失，一定要自己用 delete 歸還；忘了歸還叫記憶體洩漏，還了兩次叫重複釋放。陣列用 new double[n] 要的，要用 delete[] 歸還。

⑫ 複製物件：淺複製、深複製與三法則

寫 RateCurve b = a; 會用複製建構函數做出 a 的副本；寫 b = a;（b 已經存在）會用複製賦值運算子。沒有自己寫時，編譯器會自動產生一個「把每個成員照抄一遍」的版本。

如果成員裡有一個指向堆積陣列的指標，「照抄」只抄到位址，兩個物件會指著同一塊陣列——這叫淺複製（shallow copy）。改 b 會改到 a，兩個物件消失時還會對同一塊記憶體 delete 兩次。正確做法是深複製（deep copy）：新物件自己 new 一塊陣列，把內容一個個複製過去。

三法則（rule of three）：只要一個類別自己寫了解構函數（通常是因為它管理了 new 出來的資源），就幾乎一定也要自己寫複製建構函數與複製賦值運算子。第四題就是把這三個寫對。

C++
#include <iostream>
int main() {
    double* a = new double[3]{0.03, 0.03, 0.03};
    double* b = a;                      // 淺複製：只抄位址，a、b 指同一塊
    b[0] = 0.08;
    std::cout << a[0] << '\n';          // 0.08：改 b 改到了 a
    double* c = new double[3];          // 深複製：自己要一塊新的
    for (int i = 0; i < 3; ++i) c[i] = a[i];
    c[0] = 0.01;
    std::cout << a[0] << '\n';          // 仍是 0.08，互不影響
    delete[] a;                         // a、b 共用的那一塊只能 delete 一次
    delete[] c;
}

（5）三個階段的先後

撰寫流程補充這題是怎麼一步步想出來的

一開始我把這三個當成「三種不同的規則」，不知道它們的關係。做完（1）（2）（4）後發現它們是同一次函數呼叫的三個依序發生的步驟：

  1. 名稱查找（name lookup，編譯期）：從呼叫運算式的靜態型別的作用域開始往外找這個名字，在第一個找到的作用域就停止。遮蔽就在這一步發生——（2）的錯誤出在這裡。
  2. 重載決議（overload resolution，編譯期）：在上一步找到的那組同名函數中，依實參的型別與轉換規則選出最匹配的一個；using 宣告能讓父類別的版本進到這一組候選。
  3. 虛函數派發（virtual dispatch，執行期）：如果選中的是虛函數，而且不是用 Bond:: 這種限定名稱呼叫，就在執行時依物件的動態型別查 vtable 決定實際執行的版本——（1）的 base.payment(3) 在這一步走到子類別。

順序不能顛倒：派發只能在「已經選定的那個虛函數」的各個覆寫版本之間挑，所以前兩步失敗（例如被遮蔽）就根本走不到第三步。

可直接貼到作業第二題　思考過程（可放在報告的「問題與修正」）

前兩行照虛函數的規則就能算出 50 和 1050。第三行一開始寫成 1000，理由是 payment() 不是虛函數，以為裡面呼叫的 payment(3) 也會固定用 Bond 的版本；但同一個物件 base.payment(3) 是 1050，只多包一層就變成 1000 並不合理。詢問 AI 後理解成員函數裡的 payment(3) 等於 this->payment(3)，仍會依物件的動態型別派發，所以是 1050，執行結果也相同。第（2）小題原本以為子類別自然繼承了 payment()，取消註解編譯後才發現被遮蔽：名稱查找在子類別找到 payment 就停止。比較了三種修法（在子類別加 using、呼叫端改寫 fixed.Bond::payment()、子類別再寫一個轉呼叫的函數）後，選擇只改類別本身、改動最小的 using Bond::payment;。第（4）小題看到「marked override but does not override」時，逐字比對兩個宣告才發現少了 const，補上後再透過 const Bond& 呼叫，確認真的有覆寫。最後把（1）（2）（4）的現象對照起來，整理出名稱查找、重載決議、虛函數派發的先後順序。

可直接貼到作業第二題　學到什麼

重載、遮蔽、覆寫不是三條彼此獨立的規則，而是一次函數呼叫依序經過的三個階段；遇到「父類別明明有這個函數卻找不到」的錯誤，要先想到名稱查找被遮蔽，而不是重載或虛函數的問題。也學到兩個實用的寫法：子類別用 Bond::payment(year) 這種限定名稱呼叫父類別版本，不會觸發動態派發，也就不會無限遞迴；覆寫的函數加上 override，可以讓簽名不一致（例如少一個 const）在編譯時就被抓出來，否則程式會靜靜地變成遮蔽，結果錯了也不容易發現。

可直接貼到作業第二題　結論與論證

（1）輸出為 50、1050、1050。fixed.payment(2) 直接呼叫 FixedRateBond::payment(int)，Bond::payment(2) 為 0，加 50 得 50。base.payment(3) 雖透過 const Bond&，但 payment(int) 為虛函數，依物件動態型別派發至 FixedRateBond::payment(3)，得 1050。base.payment() 先在 Bond 中選定非虛函數 Bond::payment()，其內部的 payment(3) 等同 this->payment(3)，this 指向的物件動態型別為 FixedRateBond，因此仍派發到 FixedRateBond::payment(int)，得 1050；子類別中的 Bond::payment(year) 為限定名稱呼叫，不進行動態派發，避免無限遞迴。 （2）取消註解後無法編譯。名稱查找從 fixed 的靜態型別 FixedRateBond 開始，在子類別即找到 payment(int) 並停止，Bond 的所有同名 payment（包括 payment()）被遮蔽，重載決議只剩 payment(int)，無法匹配零個引數。修正方式是在 FixedRateBond 的 public 區加入 using Bond::payment;，將父類別的 payment 宣告引入子類別作用域；payment(int) const override 仍保留，動態派發不受影響。修正後 fixed.payment() 輸出 1050，與 base.payment() 相同。 （3）重載：不需繼承、不需 virtual、參數必須不同，影響重載決議。遮蔽：發生於繼承、不需 virtual、只要名稱相同即遮蔽，影響名稱查找。覆寫：需要繼承且父類別函數為 virtual，名稱、參數、const 等簽名必須一致，影響執行期的虛函數派發。 （4）錯誤根本原因是子類別的 payment(int) 少了 const，與 Bond::payment(int) const 的簽名不同，並未覆寫任何虛函數，因此標示 override 時編譯器報錯。最小修改為改成 double payment(int year) const override。若未寫 override，此程式會編譯成功但僅形成遮蔽，透過 Bond& 呼叫仍執行父類別版本；修正後透過 const Bond& 呼叫 payment(3) 得到 1050，驗證已真正覆寫。 （5）一次成員函數呼叫依序經過：名稱查找（編譯期，從靜態型別的作用域開始，找到名稱即停止，遮蔽在此發生）→ 重載決議（編譯期，在找到的同名函數中依引數選出最佳版本）→ 虛函數派發（執行期，若選中的是虛函數且非限定名稱呼叫，依物件動態型別透過 vtable 決定實際版本）。前兩步失敗時不會進入第三步。

（2）按值與按參考為何不同？對金融商品集合的影響

撰寫流程補充這題是怎麼一步步想出來的

一開始我以為「按值」只是「多複製一份」，內容應該一樣。後來想到複製建構才想通：形式參數 Bond b 是一個全新的 Bond 物件，它是用 Bond 的複製建構函數、從 fixed 裡的「Bond 那一部分」複製出來的——子類別的部分直接被切掉，這叫物件切割（object slicing）。新物件從頭到尾就是一個 Bond，它的 vptr 指向 Bond 的 vtable，所以呼叫的是 Bond::value()。按參考傳遞則沒有產生新物件，b 只是 fixed 的別名，動態型別仍是 FixedRateBond。

我問 AI「切割在實務上會造成什麼問題」，它舉的例子正好就是金融商品集合：如果用 std::vector<Bond> 存放各種債券，push_back(FixedRateBond(...)) 時每個物件都被切成 Bond，計算投資組合價值時所有商品都用零息債的公式算，金額錯了程式卻不會報錯——這種靜默錯誤最危險。正確做法是存指標或智慧指標：std::vector<std::unique_ptr<Bond>>（或 std::vector<Bond*> 並自行管理生命週期），函數參數用 const Bond& 或 const Bond*。我自己寫了一個小實驗確認：

我原本以為 dynamic_cast 只是比較「好看」的強制轉型。查了之後知道它和 static_cast 最大的不同是執行期檢查：它會查物件實際的動態型別（靠的是多型類別的執行期型別資訊，所以 Bond 必須至少有一個虛函數——這裡有虛解構函數）。

  • p 實際指向 FixedRateBond，轉成 FixedRateBond* 合法 → 回傳有效指標，!= nullptr 為 true。
  • pBasic 實際指向一個純 Bond 物件，它根本不是 FixedRateBond → 轉型失敗。指標版本的 dynamic_cast 失敗時回傳 nullptr，所以 == nullptr 為 true。（若是參考版本 dynamic_cast<FixedRateBond&>(basic)，失敗時會丟出 std::bad_cast 例外，因為沒有「空參考」可以回傳。）

用 static_cast<FixedRateBond*>(pBasic) 則不檢查，會得到一個「指向不存在的子類別物件」的指標，之後呼叫 couponRate() 是未定義行為。

（4）byPointer：不切割的呼叫方式

void byPointer(const Bond* p) 已加在上面的程式中，輸出第 6、7 行：byPointer(&fixed) 印 105（指標指向完整的 FixedRateBond，動態派發），byPointer(&basic) 印 100。傳的是位址，不會複製物件，自然不會切割。

先把每個運算式的靜態型別（編譯器看到的型別）和動態型別（物件實際的型別）分開列表，大部分答案就能直接推出。唯一卡住的是 byValue(fixed)：原本以為傳進去的是 fixed，結果應該也是 105。後來想到按值傳遞會用 Bond 的複製建構函數建立一個新的 Bond 物件，只複製到 fixed 裡屬於 Bond 的部分，子類別的部分被切掉，所以呼叫的是 Bond::value()，得到 100。為了確認這在實務上的影響，另外寫了一個小程式比較 vector 和 vector<unique_ptr> 的總值，前者因為切割而少算。dynamic_cast 原本以為只是另一種寫法的強制轉型，查證後才知道它會在執行期檢查實際型別，指標版本失敗時回傳 nullptr，所以第二次轉型的判斷結果是 true。

可直接貼到作業第三題　學到什麼

多型只有透過參考或指標才會作用，按值傳遞具體基底類別會發生物件切割，而且編譯器不會提出任何警告，很難察覺。存放各種金融商品的集合要放指標或智慧指標（例如 vector<unique_ptr>），函數參數用 const Bond& 或 const Bond*。如果基底類別不需要單獨建立物件，可以設計成有純虛函數的抽象類別，按值傳遞時就會直接編譯失敗。另外也釐清了 dynamic_cast 和 static_cast 的差別：前者有執行期檢查，轉型失敗時指標得到 nullptr，參考則丟出 std::bad_cast。

可直接貼到作業第三題　結論與論證

（1）五行輸出依序為 105、100、105、true、true。p 的靜態型別為 Bond、動態型別為 FixedRateBond，value() 為虛函數，輸出 105。byValue(fixed) 的參數 b 靜態與動態型別皆為 Bond（由 fixed 複製出的新 Bond 物件），輸出 100。byReference(fixed) 的 b 靜態型別為 const Bond&、動態型別為 FixedRateBond，輸出 105。dynamic_cast(p) 成功，不為 nullptr，輸出 true；dynamic_cast(pBasic) 因 pBasic 實際指向 Bond 物件而失敗，結果為 nullptr，輸出 true。 （2）按值傳遞時，形式參數 Bond b 是以 Bond 的複製建構函數從 fixed 的基底部分建立的新物件，衍生類別的部分被切除（object slicing），新物件的動態型別就是 Bond，因此呼叫 Bond::value()。按參考傳遞不產生新物件，b 只是 fixed 的別名，仍依動態型別派發到 FixedRateBond::value()。若金融商品集合以 std::vector 按值存放，所有衍生商品都會被切割成 Bond，評價時全部套用基底類別的現金流公式，結果錯誤而程式不會報錯；以小程式驗證，兩張固定票息債按值存放時總值為 200，存放 unique_ptr 時為 210。集合應存放指標或智慧指標，函數參數使用 const Bond& 或 const Bond。 （3）dynamic_cast 會在執行期依物件的實際動態型別檢查轉型是否合法（需要多型類別，Bond 具有虛擬解構函數）。p 指向 FixedRateBond 物件，轉型成功取得有效指標；pBasic 指向純 Bond 物件，不是 FixedRateBond，轉型失敗。指標版本失敗時回傳 nullptr；參考版本失敗時則丟出 std::bad_cast 例外。 （4）新增 void byPointer(const Bond* p) { std::cout << p->value() << '\n'; }，以位址傳遞不複製物件、不發生切割。byPointer(&fixed) 預期且實測輸出 105，byPointer(&basic) 輸出 100。

（1）a 與 b 的 rates_ 指向何處

撰寫流程補充這題是怎麼一步步想出來的

我先畫記憶體圖。RateCurve a(3, 0.03) 在 heap 配置一塊 3 個 double 的陣列，a.rates_ 存它的位址。RateCurve b = a; 是複製建構——類別沒有自己寫，編譯器產生的版本做的是逐一複製成員：b.n_ = a.n_、b.rates_ = a.rates_。我原本以為「複製物件」就是「複製一切」，但這裡複製的只是指標的值（位址），heap 上那塊陣列並沒有被複製。

文字
stack                          heap
a: n_=3, rates_ ──┐
                  ├──▶ [0.03, 0.03, 0.03]   ← 只有一塊
b: n_=3, rates_ ──┘

所以有兩個物件（a、b 各自是獨立的 RateCurve，有不同的位址），卻共用同一份動態資源。b.set(0, 0.08) 透過 b.rates_ 改了那塊陣列，a.at(0) 讀的是同一塊，所以會讀到 0.08，而不是 0.03——修改 b 意外改到了 a。

（2）離開作用域時的記憶體問題

撰寫流程補充這題是怎麼一步步想出來的

我一開始想寫「程式會當機」，但想到題目說「不要假設必然正常或必然當機」，就把「會發生什麼」和「標準怎麼說」分開。離開 main 時，區域物件以建構的相反順序解構：先 b、再 a。

  1. b 解構：delete[] b.rates_，那塊陣列被釋放。此時 a.rates_ 變成懸空指標（dangling pointer）。
  2. a 解構：delete[] a.rates_——對同一塊已釋放的記憶體再釋放一次，這是重複釋放（double delete / double free）。

依 C++ 標準，對已釋放的記憶體再 delete[] 屬於未定義行為（undefined behavior）：可能直接中止、可能看起來正常結束、可能悄悄破壞 heap 讓之後的程式出錯，結果和編譯器、作業系統、最佳化設定有關，不能假設必然當機或必然正常。另外，如果在 b 解構之後還有人用 a.at(0)，那就是使用已釋放的記憶體（use-after-free），同樣是未定義行為。

我沒有直接執行原版，而是問 AI「怎麼安全地證明它真的會重複釋放」。AI 建議用編譯器內建的 AddressSanitizer（-fsanitize=address）：它會在每次 delete 時檢查，一發現重複釋放就立刻停止程式並報告位置，所以不會真的讓未定義行為擴散。下面是我在 Linux 上檢查的結果（Mac 的 clang++ 也支援同一個參數，這一步是選做的驗證，不是作業要求執行原版）：

（3）改寫 RateCurve：解構、複製建構、複製賦值

這題要保留「自己管理動態陣列」的設計，所以不能偷懶改成 std::vector（那是零法則的做法，我放在最後當延伸）。這裡要用三法則：只要類別自己寫了解構函數來釋放資源，通常就也要自己寫複製建構與複製賦值。

  • 複製建構：簡單——新物件自己 new 一塊同樣大小的陣列，把元素一個個複製過來（深複製）。
  • 複製賦值：我的第一版是「先 delete[] rates_，再 new 新陣列、複製」。寫完自己檢查兩個情境就發現問題： 1. 自我賦值 c = c：一開始就把自己的陣列刪了，接著要從 other.rates_（就是剛刪掉的那塊）複製，等於讀已釋放的記憶體。所以要先檢查 if (this == &other) return *this;。 2. 我問 AI 還有沒有漏掉什麼，它提醒：如果「先刪舊的」之後 new 失敗丟出例外（記憶體不足），物件會留下一個指向已釋放記憶體的 rates_，之後解構又會重複釋放。比較安全的順序是先配置並複製到新陣列，成功後才釋放舊陣列，最後再更新指標與長度。這也順便處理了「不同大小的曲線」：長度 n_ 跟著新陣列一起更新。
  • 建構函數：多加了 n <= 0 的檢查；at()、set() 加上索引範圍檢查（原版越界存取也是未定義行為）。

// 第四題（3）（4）：保留動態陣列，自己實作三法則（解構、複製建構、複製賦值）
// 編譯：clang++ -std=c++17 -Wall -Wextra -pedantic Q4_rate_curve_fixed.cpp -o Q4
#include <iostream>
#include <stdexcept>

class RateCurve {
    int n_;
    double* rates_;
public:
    RateCurve(int n, double initial) : n_(n), rates_(nullptr) {
        if (n <= 0) throw std::invalid_argument("曲線長度必須是正整數");
        rates_ = new double[n_];
        for (int i = 0; i < n_; ++i) rates_[i] = initial;
    }

    // 解構函數：new[] 配 delete[]
    ~RateCurve() { delete[] rates_; }

    // 複製建構：為新物件配置「自己的」陣列，再逐一複製（深複製）
    RateCurve(const RateCurve& other) : n_(other.n_), rates_(new double[other.n_]) {
        for (int i = 0; i < n_; ++i) rates_[i] = other.rates_[i];
    }

    // 複製賦值：先配置新陣列並複製完成，再釋放舊陣列
    RateCurve& operator=(const RateCurve& other) {
        if (this == &other) return *this;            // 自我賦值：什麼都不用做
        double* fresh = new double[other.n_];       // 若 new 失敗丟出例外，*this 完全沒被改到
        for (int i = 0; i < other.n_; ++i) fresh[i] = other.rates_[i];
        delete[] rates_;                             // 新資料準備好了才釋放舊的
        rates_ = fresh;
        n_ = other.n_;                               // 長度一起更新：處理不同大小的曲線
        return *this;
    }

    int size() const { return n_; }
    double at(int i) const {
        if (i < 0 || i >= n_) throw std::out_of_range("索引超出曲線長度");
        return rates_[i];
    }
    void set(int i, double value) {
        if (i < 0 || i >= n_) throw std::out_of_range("索引超出曲線長度");
        rates_[i] = value;
    }
    const double* data() const { return rates_; }   // 只用來印位址、驗證是否共用
};

    std::cout << name << "（長度 " << c.size() << "）：";
    for (int i = 0; i < c.size(); ++i) std::cout << c.at(i) << ' ';
    std::cout << '\n';
}

可直接貼到作業第四題　學到什麼

類別只要用原始指標擁有動態資源，編譯器預設的複製就只是複製位址，會造成共用資料、重複釋放等問題，所以解構函數、複製建構函數、複製賦值運算子要一起寫（三法則）。複製賦值除了深複製，還要處理自我賦值、例外安全（先配置後釋放）與長度不同的情況，細節比想像中多。也因此理解為什麼實務上更推薦零法則：直接改用 std::vector，三個函數都不用自己寫就能得到正確的深複製。驗證記憶體錯誤時，AddressSanitizer 比肉眼檢查或碰運氣執行可靠得多。

可直接貼到作業第四題　結論與論證

（1）RateCurve a(3, 0.03) 在 heap 配置一塊 3 個 double 的陣列，a.rates_ 儲存其位址。RateCurve b = a 呼叫編譯器產生的複製建構函數，逐一複製成員，b.rates_ 得到與 a.rates_ 相同的位址，heap 上的陣列並未被複製（淺複製）。因此 a 與 b 是兩個獨立的物件，卻共用同一份動態資源；b.set(0, 0.08) 修改的是共用陣列，a.at(0) 會讀到 0.08 而非 0.03。 （2）離開作用域時依建構的相反順序先解構 b、再解構 a。b 的解構函數 delete[] 共用陣列後，a.rates_ 成為懸空指標；a 的解構函數再次 delete[] 同一位址，屬於重複釋放（double delete），依 C++ 標準為未定義行為，可能中止、看似正常結束或破壞 heap，不能假設必然當機或必然正常；若在 b 解構後仍存取 a.at()，則為使用已釋放記憶體（use-after-free），同樣是未定義行為。未直接執行原版，而是以 AddressSanitizer（-fsanitize=address）編譯檢查，工具在第二次 delete[] 時即中止並回報 attempting double-free，與分析一致。 （3）依三法則改寫：解構函數以 delete[] 釋放陣列；複製建構函數為新物件配置同樣大小的新陣列並逐一複製元素（深複製）；複製賦值運算子先檢查自我賦值（this == &other），再配置新陣列並複製完成後才 delete[] 舊陣列、更新指標與長度 n_，最後回傳 *this。先配置後釋放可確保 new 失敗丟出例外時原物件不被破壞，同時處理不同長度曲線的賦值。另加入長度與索引的檢查。 （4）測試一：b 由 a 複製建構後修改 b，a.at(0) 仍為 0.03 且兩者陣列位址不同；測試二：長度 2 的曲線被賦值為長度 5 的曲線、長度 4 的曲線被賦值為長度 1 的臨時物件，長度與內容皆正確，賦值後修改來源不影響目標；測試三：自我賦值 c = c 後內容不變；另測試連續賦值 x = y = c 與非法長度 0 會丟出例外。修正版以 AddressSanitizer 執行無任何錯誤，確認每次 new[] 都恰好對應一次 delete[]。

撰寫流程補充第五題的設計是怎麼一步步定下來的

第一版想法：一個大函數。 我最先想到的是寫一個 npv(type, F, T, c, y, method)，裡面用 if (type == "fixed")、if (method == "continuous") 分情況算——這是我寫 R 的習慣，從頭寫到尾。但題目明確禁止 switch(type) 取代虛函數，而且這種寫法彈性很小，換個模型就要在程式中間大改。三種債券 × 兩種折現就有 6 種組合，再加一種商品就要改每一個 if。

第二版：商品與折現方法分開。 改用策略模式的拆法：商品只負責「現金流是什麼」，引擎只負責「怎麼折現」，定價器把兩者組合起來。於是： - Bond::payment(t) 是虛函數：各種債券覆寫它，定價器不用知道是哪一種債券。 - DiscountEngine::factor(t) 是虛函數：兩種折現方法覆寫它，定價器不用知道是哪一種折現。 - BondPricer::npv() 只寫一次迴圈 Σ payment(t) × factor(t)，新增商品或折現方法都不用改它——這就是「降低耦合」。

卡住的地方 1：子類別怎麼重用父類別的「到期還本」？ 我原本在 FixedRateBond::payment 裡寫 if (t == T) return F * c + F;。寫到 StepUpBond 又要寫一次，覺得重複。後來想到第二題剛學到的 Bond::payment(t)（限定名稱、不派發）：父類別的零息債版本剛好就是「到期日還本金、其他年份 0」，所以子類別寫成「票息 + Bond::payment(t)」，本金的邏輯只寫在一個地方。

卡住的地方 2：引擎要用參考還是指標？ 題目說定價器「不擁有引擎、可以切換引擎」。我第一個寫法是成員 const DiscountEngine& engine_;，結果寫 setEngine() 時發現參考綁定之後不能改綁，只能用指標。所以改成 const DiscountEngine* engine_：建構和 setEngine() 都接收 const DiscountEngine&（保證呼叫端給的是一個真的物件、不會是空指標），內部存它的位址。它是非擁有指標：定價器絕不 delete 它，引擎由 main 建立和管理。

卡住的地方 3：非法輸入要在哪裡擋？ 一開始我在 npv() 裡檢查殖利率是否為負，問 AI 後改成在建構函數裡檢查：不合法的物件根本不該被建立出來，之後所有成員函數都可以假設資料是合法的。檢查失敗就丟 std::invalid_argument。AI 也提醒我 NaN 的陷阱：y < 0 對 NaN 是 false，NaN 會通過「非負」的檢查，所以要先用 std::isfinite() 擋掉 NaN 和無窮大。

卡住的地方 4：怎麼確認「非有限值不會被判為通過」？ 我的比較函數一開始是 std::abs(actual - expected) <= 1e-6。我想到 NaN 的任何比較都是 false，所以 NaN 剛好會 FAIL；但 AI 指出依賴這個「剛好」不夠明確，而且如果有人把條件改寫成 !(diff > tol)，NaN 就會變成通過。所以我明確寫成 std::isfinite(actual) && std::abs(actual - expected) <= TOL，並在程式裡直接拿 NaN 和無窮大測試這個函數，印出它們都不通過。

// 編譯：clang++ -std=c++17 -Wall -Wextra -pedantic Q5_bond_pricer.cpp -o Q5
#include <cmath>
#include <iomanip>
#include <iostream>
#include <limits>
#include <stdexcept>
#include <string>

// ---------- 輸入檢查（建構時就擋掉不合法的參數）----------
void requirePositive(double x, const std::string& name) {
    if (!std::isfinite(x) || x <= 0.0)
        throw std::invalid_argument(name + " 必須是有限的正數");
}
void requireNonNegative(double x, const std::string& name) {
    if (!std::isfinite(x) || x < 0.0)
        throw std::invalid_argument(name + " 必須是有限且非負的數");
}
void requirePositiveInt(int n, const std::string& name) {
    if (n <= 0)
        throw std::invalid_argument(name + " 必須是正整數");
}

// ---------- 債券：具體基底類別（零息債）----------
class Bond {
public:
    Bond(double face, int maturity) : face_(face), maturity_(maturity) {
        requirePositive(face, "面額 F");
        requirePositiveInt(maturity, "年期 T");
    }
    virtual ~Bond() = default;

    // 第 t 年年底的現金流；零息債只有到期日還本金
    virtual double payment(int t) const {
        return t == maturity_ ? face_ : 0.0;
    }
    double face() const { return face_; }
    int maturity() const { return maturity_; }

private:
    double face_;
    int maturity_;
};

class FixedRateBond : public Bond {
public:
    FixedRateBond(double face, int maturity, double coupon)
        : Bond(face, maturity), coupon_(coupon) {
        requireNonNegative(coupon, "票息率 c");
    }
    double payment(int t) const override {
        if (t < 1 || t > maturity()) return 0.0;
        return face() * coupon_ + Bond::payment(t);   // 票息 + （到期時的）本金
    }

private:
    double coupon_;
};

class StepUpBond : public Bond {
public:
    StepUpBond(double face, int maturity, double c0, double step)
        : Bond(face, maturity), c0_(c0), step_(step) {
        requireNonNegative(c0, "起始票息率 c0");
        requireNonNegative(step, "階梯增加率 dc");
    }
    double payment(int t) const override {
        if (t < 1 || t > maturity()) return 0.0;
        double rate = c0_ + (t - 1) * step_;          // 第 t 年的票息率
        return face() * rate + Bond::payment(t);
    }

private:
    double c0_;
    double step_;
};

// ---------- 折現引擎：具體基底類別（年複利）----------
class DiscountEngine {
public:
    explicit DiscountEngine(double y) : y_(y) { requireNonNegative(y, "殖利率 y"); }
    virtual ~DiscountEngine() = default;
    virtual double factor(int t) const { return 1.0 / std::pow(1.0 + y_, t); }
    double yield() const { return y_; }

private:
    double y_;
};

class ContinuousDiscountEngine : public DiscountEngine {
public:
    explicit ContinuousDiscountEngine(double y) : DiscountEngine(y) {}
    double factor(int t) const override { return std::exp(-yield() * t); }
};

// ---------- 定價器：不擁有引擎，只「借用」----------
class BondPricer {
public:
    explicit BondPricer(const DiscountEngine& engine) : engine_(&engine) {}
    void setEngine(const DiscountEngine& engine) { engine_ = &engine; }

    double npv(const Bond& bond) const {
        double sum = 0.0;
        for (int t = 1; t <= bond.maturity(); ++t)
            sum += bond.payment(t) * engine_->factor(t);   // 兩個虛函數呼叫
        return sum;
    }

private:
    const DiscountEngine* engine_;   // 非擁有（non-owning）指標：不負責 delete
};

// ---------- 測試工具 ----------
const double TOL = 1e-6;
int passed = 0, failed = 0;

bool closeEnough(double actual, double expected) {
    // 先確認是有限值：NaN 和 inf 一律不算通過
    return std::isfinite(actual) && std::abs(actual - expected) <= TOL;
}

void check(const std::string& name, double actual, double expected) {
    bool ok = closeEnough(actual, expected);
    std::cout << (ok ? "[PASS] " : "[FAIL] ") << name
              << "：計算 " << actual << "，預期 " << expected
              << "，誤差 " << std::scientific << std::setprecision(2) << std::abs(actual - expected)
              << std::fixed << std::setprecision(6) << '\n';
    (ok ? passed : failed)++;
}

int main() {
    std::cout << std::fixed << std::setprecision(6);

    // 1. 折現引擎由 main 建立與管理（在 stack 上，整個 main 期間都有效）

設計說明（報告需要的論述）

  • 多型如何降低耦合： BondPricer::npv() 只依賴兩個介面——Bond::payment(int) const 和 DiscountEngine::factor(int) const。它不知道、也不需要知道傳進來的是哪一種債券或哪一種折現法；呼叫時由虛函數依物件的動態型別決定實際算法。新增一種債券（例如浮動利率債）只要寫一個覆寫 payment 的子類別；新增一種折現法（例如半年複利）只要寫一個覆寫 factor 的子類別；BondPricer 和其他類別一行都不用改。這和 QuantLib 把商品（Instrument）與定價引擎（PricingEngine）分開的設計是同一個想法。
  • 生命週期與所有權：
  • 債券：main 用 new 建立、以 Bond* 持有，由 main 擁有；用完以 delete 釋放。因為 Bond 有虛解構函數，透過 Bond* 刪除子類別物件時會正確呼叫子類別的解構函數（第一題（3）的教訓）。每個 new 恰好一個 delete（避免洩漏與重複釋放），delete 後立刻設為 nullptr（避免懸空指標被誤用）。
  • 引擎：在 main 的 stack 上建立，由 main 擁有，離開 main 時自動解構；它們的生命期涵蓋所有計價動作。
  • BondPricer：只借用引擎（非擁有指標），不負責釋放；呼叫端必須保證「引擎比定價器活得久」。如果把一個臨時的引擎物件傳給 setEngine()，之後再計價就是懸空指標——這是這種設計需要文件說明的限制。若要讓定價器共同擁有引擎，可以改用 std::shared_ptr<const DiscountEngine>。
  • 為什麼不用 switch／typeid： 那會讓 BondPricer 必須認識每一種債券與折現法，每新增一種就要修改它，違反題目要求，也失去多型的意義。本程式沒有使用任何 switch、typeid 或 dynamic_cast。
  • 數值驗證條件： 六組全部以「計算值為有限值，且與參考值的絕對誤差 ≤ 1e-6」判定通過；實測最大誤差約 3.3 × 10⁻⁷（參考值本身只給到小數第 6 位）。NaN 與無窮大經過同一個判斷函數都回傳 false。
可直接貼到作業第五題　思考過程（可放在報告的「問題與修正」）

最初的想法是寫一個大函數，用 if 判斷債券種類和折現方法分別計算，但三種債券乘上兩種折現就有六種組合，之後每多一種商品都要回來改每個判斷，題目也禁止用 switch 取代虛函數。因此改成把「現金流」和「折現方法」分開：債券只負責 payment(t)，折現引擎只負責 factor(t)，定價器用同一個迴圈相乘加總。實作時遇到幾個問題：固定票息債和階梯票息債都要處理到期還本，原本各寫一次，後來改成在子類別呼叫 Bond::payment(t)，重用零息債的還本邏輯；定價器一開始用參考保存引擎，寫到 setEngine() 才發現參考綁定後不能改綁，所以改成以參考傳入、以 const 指標保存，並定位為不擁有引擎的指標；參數檢查原本放在 npv() 裡，詢問 AI 後改到建構函數，讓不合法的物件無法被建立，也得知 NaN 會通過 y < 0 這類檢查，所以先用 std::isfinite() 判斷。測試判斷式原本只比較誤差，雖然 NaN 剛好會判為失敗，但為了不依賴這個巧合，明確加上 isfinite，並實際用 NaN 和無窮大測試。最後手算固定票息債的 NPV，確認與程式結果一致。

可直接貼到作業第五題　學到什麼

這題最大的收穫是理解多型在設計上的用途：把會變的部分（債券的現金流、折現方式）放進虛函數，固定的流程（加總折現後的現金流）只寫一次，之後新增商品或折現方法只要多寫一個子類別，定價器完全不用改，也就是降低耦合。另外也學到要清楚區分誰擁有物件：用 new 建立的債券由 main 負責 delete，引擎只是借給定價器使用，非擁有指標不能 delete，而且要確保引擎的生命期比使用它的定價器長。數值程式的測試也不能只比較誤差，還要排除 NaN 與無窮大，並在建構時就擋掉不合法的參數。

可直接貼到作業第五題　結論與論證

設計上將「現金流」與「折現方法」分離：Bond 為具體基底類別（零息債，僅到期日支付面額），具有虛擬解構函數與 virtual double payment(int t) const；FixedRateBond 與 StepUpBond 以 override 覆寫 payment，票息分別為 F×c 與 F×(c0+(t−1)Δc)，並以 Bond::payment(t) 重用到期還本的邏輯。DiscountEngine 為具體基底類別，儲存殖利率 y，virtual double factor(int t) const 計算 1/(1+y)^t；ContinuousDiscountEngine 以 override 改為 exp(−yt)。BondPricer 以 const Bond& 接收債券，內部保存 const DiscountEngine（以參考傳入、以指標保存，才能用 setEngine() 切換），NPV 為 Σ payment(t)×factor(t)，兩者皆透過虛函數於執行期決定實際算法，未使用 switch、typeid 或 dynamic_cast。因此新增債券種類或折現方法只需新增子類別，BondPricer 與既有類別不需修改，降低了債券與折現方法之間的耦合。 所有參數在建構函數中檢查：F 必須為有限正數、T 為正整數、票息率、階梯增加率與殖利率必須為有限非負數，不合法即丟出 std::invalid_argument；檢查先使用 std::isfinite()，避免 NaN 因比較皆為 false 而通過非負檢查。 記憶體管理方面，main 以 new 建立 Bond、FixedRateBond、StepUpBond（另建立一張平價驗算用的 FixedRateBond），以 Bond 指向並由 main 擁有，計價完成後逐一 delete 並設為 nullptr；Bond 具有虛擬解構函數，透過 Bond* 刪除衍生類別物件時會正確呼叫衍生類別的解構函數。折現引擎建立於 main 的 stack 上，由 main 擁有並在整個計價期間有效；BondPricer 只保存非擁有指標，不負責釋放引擎，使用者須確保引擎的生命期長於定價器的使用期間。 測試以「計算值為有限值且與參考值絕對誤差不大於 1e-6」判定通過，六組必測資料（零息債年複利 888.996359、固定票息債年複利 1027.750910、階梯票息債年複利 999.274579、平價驗算 1000、固定票息債零殖利率 1150、固定票息債連續複利 1025.461748）全部通過，最大絕對誤差約 3.3×10⁻⁷；並以 NaN 與無窮大測試判斷函數，皆判定為不通過。非法輸入測試包含 F=−1000、T=0、Δc=−1%、y=−2% 與 y=NaN，皆由建構函數丟出例外並印出錯誤訊息。另以固定票息債年複利手算 50/1.04+50/1.04²+1050/1.04³=1027.750910，與程式結果一致。
