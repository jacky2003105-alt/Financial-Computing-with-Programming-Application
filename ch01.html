1.1C++ 是什麼

一句話介紹

C++ 是 1980 年代由 Bjarne Stroustrup 在 AT&T 貝爾實驗室，以 C 語言為基礎發展出來的程式語言。它保留了 C 的「貼近硬體、執行很快」，再加上類別（class）、模板（template）、運算子多載、虛擬函數等功能，讓大型程式也能寫得有條理。

老師講義整理的特性：

  • C 是 C++ 的子集合：大部分 C 程式拿到 C++ 也能編譯。
  • 同時有低階與高階的特性：可以直接操作記憶體位址（低階），也可以用類別、模板把概念包裝起來（高階）。
  • 執行速度快：適合高效能計算、即時處理——這正是金融業需要的。
  • 支援多種寫法（範式）：程序導向、物件導向、泛型程式設計、函數式程式設計。
  • 能和很多程式庫整合：Boost、Eigen（矩陣運算）、OpenMP（平行運算）、CUDA（GPU），以及這門課的主角 QuantLib（開源的量化金融程式庫）。

版本：傳統 C++ 與現代 C++

版本 年份 重點
C++98 / C++03 1998 / 2003 第一個標準與小修訂，一般稱為「傳統 C++」
C++11 2011 大改版，從這裡開始稱為「現代 C++」：auto、範圍 for、智慧指標、lambda
C++14 2014 補強 C++11
C++17 2017 std::optional、if constexpr、結構化綁定
C++20 2020 concepts、ranges、coroutines
C++23 2023 持續擴充標準程式庫
C++26 制定中 —

老師特別提醒：「現代 C++」不只是版本號，而是一種寫法風格——讓編譯器幫你推導型別、讓資源自動管理（RAII）、多用標準程式庫，少自己手動管理記憶體。這份筆記的程式都用 C++20 編譯。

金融應用為什麼金融業用 C++

銀行的定價引擎、風險系統、高頻交易系統大多用 C++ 寫：一個風險報表可能要對幾十萬筆部位、上千個情境重新評價，速度差 10 倍就是「下班前算得完」和「算不完」的差別。QuantLib 就是用 C++ 寫的，Python 的 QuantLib 套件其實是在呼叫底層的 C++ 程式。常見的分工是：研究、畫圖用 Python／R，正式上線的計算核心用 C++。

老師的課程規劃

  • 金融計算程式運用（一）：「初階 C++」，語法基礎＋財務案例。
  • 金融計算程式運用（二）：物件導向、模板、C++ 標準程式庫，以及 QuantLib 原始碼的閱讀。
  • 參考書：Armstrong《C++ for Financial Mathematics》、Pitt-Francis & Whiteley《Guide to Scientific Computing in C++》、Lippman《C++ Primer》、Duffy《Financial Instrument Pricing Using C++》。

Q3

簡答｜中為什麼金融用 C++

用自己的話說明：為什麼量化金融的計算核心（例如定價、風險引擎）常用 C++ 撰寫？

答案

C++ 是編譯式語言，編譯後直接變成機器碼執行，速度比直譯式語言快很多；又能控制記憶體使用，適合大量重複的數值計算（例如對大量部位、大量情境重新評價、蒙地卡羅模擬）。它也有成熟的金融程式庫 QuantLib 和數值程式庫（Eigen、Boost），並能用類別與模板把金融商品、定價方法整理成結構清楚的大型程式。

1.2編譯式語言：和 R、Python 有什麼不同

直譯 vs 編譯

直譯式（R、Python） 編譯式（C++）
執行方式 直譯器一行一行讀、一行一行執行 先用編譯器把整份程式翻譯成機器碼（執行檔），再執行執行檔
錯誤什麼時候發現 執行到那一行才發現 很多錯誤在編譯時就被抓出來，程式根本不會開始跑
速度 較慢 快（迴圈多時常差數十倍以上）
型別 變數可以隨時裝不同型別的東西 強型別：每個變數一開始就要宣告型別，不能亂換
試東西 很方便，打一行看一行 要寫完整的程式、編譯、再執行

用一個比喻：直譯像口譯，講者說一句、口譯員翻一句；編譯像筆譯，整本書先翻好印成冊，讀者拿到的就是翻好的版本，讀起來快，但改一個字要重新印。

同一件事，R 和 C++ 的寫法

在 R 裡算 1 加到 100：

文字
total <- 0
for (i in 1:100) total <- total + i
total

C++ 寫成：

C++
#include <iostream>

int main() {
    int total = 0;                    // 宣告一個整數變數，初值 0
    for (int i = 1; i <= 100; i++) {  // i 從 1 跑到 100
        total = total + i;
    }
    std::cout << total << std::endl;  // 印出結果
    return 0;
}

5050

差別一眼可見：C++ 要寫 #include、要有 main()、變數前面要寫型別 int、每個敘述結尾要有分號 ;、輸出要用 std::cout。這些「儀式」每一個都有它的道理，接下來會一一說明。

Q1

選擇｜易編譯式語言

關於 C++ 是「編譯式語言」，下列敘述何者正確？

  1. (A)程式會一行一行邊翻譯邊執行，不會產生執行檔
  2. (B)編譯只會檢查縮排，型別錯誤要執行時才會發現
  3. (C)程式寫完不用任何處理，作業系統可以直接讀 .cpp 檔
  4. (D)執行前先由編譯器把原始碼翻成機器碼，產生執行檔
答案 (D)

執行前先由編譯器把原始碼翻成機器碼，產生執行檔

解析

C++ 的原始碼（.cpp）要先經過編譯、連結產生執行檔，才能執行。型別錯誤、語法錯誤大多在編譯時就會被抓出來。(A) 是直譯式語言的做法。

Q2

簡答｜中強型別

C++ 是「強型別語言」，這是什麼意思？對寫程式有什麼好處與麻煩？

答案

每個變數、每個物件在使用前都必須宣告型別（例如 int、double），之後只能裝那種型別的資料。好處是很多錯誤（例如把文字當數字相加）在編譯時就會被發現，編譯器也能依型別產生更快的機器碼；麻煩是要多寫型別、不能像 R 一樣隨手把變數改裝別種資料，型別不合時要明確轉換。

1.3第一支程式：Hello Quant World

老師講義的第一支程式：

C++
// test.cpp，放入 src 資料夾
// 這是單行註解

/*
 * 這是多行註解
 * 這是多行註解
 */

#include <iostream>                                 // 包含 iostream 標頭檔

int main(int argc, char* argv[])
{
    std::cout << "Hello Quant World" << std::endl;  // std 是標準程式庫的命名空間
    return 0;
}

Hello Quant World

逐行拆解：

  • // 後面到行尾是單行註解；/* ... */ 之間是多行註解。註解是寫給人看的，編譯器會整個忽略。
  • #include <iostream>：告訴編譯器「我要用 iostream（input/output stream，輸入輸出）程式庫」。< > 裡是標頭檔名稱。# 開頭的指令叫前處理指令，要單獨寫一行、放在所有函數外面（通常是檔案最上面）。
  • int main(...)：main 函數是程式的入口點，執行程式時就是從 main 的第一行開始跑。一個程式有、而且只能有一個 main。
    • int 是 main 的回傳型態，規定必須是 int（整數）。
    • 括號裡的 int argc, char* argv[] 是「命令列參數」（執行程式時在後面附加的文字），初學時用不到，可以寫成空的 int main()。
  • { 到 }：函數體，main 要做的事都寫在這對大括號裡。
  • std::cout << "Hello Quant World" << std::endl;：把文字輸出到螢幕（下一節細講）。
  • return 0;：main 結束，回傳 0 給作業系統，代表「執行成功」；非 0 通常代表發生某種錯誤。
  • 結尾的 ;：C++ 大部分的敘述（statement）都以分號結束，就像中文句子結尾的句號。

最精簡、能編譯的版本長這樣：

C++
#include <iostream>
int main() {
    std::cout << "Hello Quant World\n";
}

Hello Quant World

main 最後如果沒寫 return 0;，編譯器會自動當作回傳 0（只有 main 有這個特例，其他函數不行）。

檔名與副檔名

副檔名 用途
.cpp、.cxx、.cc 原始檔（source file）：放程式的實作
.h、.hpp 標頭檔（header file）：放宣告，給其他檔案 #include
.o（Linux/Mac）、.obj（Windows） 編譯後的目標檔
沒有副檔名（Linux/Mac）、.exe（Windows） 執行檔
換個角度想自己動手改改看
  1. 把 "Hello Quant World" 換成自己的名字。
  2. 多寫一行 std::cout << "第二行\n";，看看輸出變成兩行。
  3. 故意把分號刪掉，看看編譯器說什麼（下一節有示範）。

1.4語法的基本規矩與錯誤訊息

分號、大括號、大小寫

  • 分號：每個敘述結尾要有 ;。漏掉是新手最常見的錯誤。
  • 大括號：{ } 圍出一個「區塊」（函數體、迴圈內容…），一定要成對。
  • 區分大小寫：Main、MAIN 和 main 是不同的名字；Std::Cout 也不行。
  • 空白與換行：大部分地方可以隨便加空白、換行，編譯器不在意；縮排是為了讓人好讀（R 也是）。

讀懂編譯錯誤訊息

故意漏掉分號：

C++
#include <iostream>

int main() {
    std::cout << "Hello" << std::endl
    return 0;
}

main.cpp:4:38: error: expected ‘;’ before ‘return’
    4 |     std::cout << "Hello" << std::endl
      |                                      ^
      |                                      ;
    5 |     return 0;
      |     ~~~~~~

錯誤訊息的格式是 檔名:行號:欄位: error: 說明。這裡說第 4 行預期在 return 之前有一個 ;——編譯器常常是在「下一行」才發現上一行少東西，所以錯誤行號附近的上一行也要一起看。

把 cout 拼錯：

C++
#include <iostream>

int main() {
    std::count << "Hello" << std::endl;
    return 0;
}

main.cpp:4:10: error: ‘count’ is not a member of ‘std’; did you mean ‘cout’?
    4 |     std::count << "Hello" << std::endl;
      |          ^~~~~
      |          cout

編譯器說 count 不是 std 裡的成員，還很貼心地問「你是不是要打 cout」。

忘記 #include <iostream>：

C++
int main() {
    std::cout << "Hello" << std::endl;
    return 0;
}

main.cpp:2:10: error: ‘cout’ is not a member of ‘std’
    2 |     std::cout << "Hello" << std::endl;
      |          ^~~~
main.cpp:1:1: note: ‘std::cout’ is defined in header ‘<iostream>’; did you forget to ‘#include <iostream>’?
  +++ |+#include <iostream>
    1 | int main() {
main.cpp:2:34: error: ‘endl’ is not a member of ‘std’
    2 |     std::cout << "Hello" << std::endl;
      |                                  ^~~~
main.cpp:1:1: note: ‘std::endl’ is defined in header ‘<ostream>’; did you forget to ‘#include <ostream>’?
  +++ |+#include <ostream>
    1 | int main() {

編譯器說 cout 不是 std 的成員，接著的 note 直接提示：std::cout 定義在 <iostream>，你是不是忘了 #include <iostream>？新版編譯器的錯誤訊息常常連解法都告訴你，一定要讀。

重點看錯誤訊息的三個步驟
  1. 只看第一個 error（後面的錯誤常常是被第一個連帶引起的）。
  2. 看行號，連同上一行一起檢查。
  3. 讀 error 後面的英文說明，關鍵字常常是：expected（少了什麼）、was not declared（名字沒宣告或拼錯）、no match for（型別不合）。

語法錯誤 vs 邏輯錯誤

  • 語法錯誤：違反 C++ 規則，編譯就失敗，編譯器會告訴你哪裡錯。
  • 邏輯錯誤：程式能編譯、能執行，但結果不對（例如利率打成 5 而不是 0.05）。編譯器不會提醒，只能靠自己檢查結果。
C++
#include <iostream>

int main() {
    double principal = 1000;   // 本金
    double rate = 5;           // 邏輯錯誤：年利率 5% 應該寫 0.05
    std::cout << "一年後本利和：" << principal * (1 + rate) << std::endl;
    return 0;
}

一年後本利和：6000

編譯完全沒問題，但 1000 元一年後變 6000 元顯然不合理——這就是邏輯錯誤。

第一段第二段
  • std::cout（character output）是代表「螢幕輸出」的物件。
  • << 是輸出運算子，可以想成箭頭：把右邊的東西「推進」左邊的 cout。可以一路串下去。
  • 文字要用雙引號 "..."；數字、算式不用，會先算好再印。
  • std::endl 和 "\n" 都會換行。差別是 endl 還會「立刻把緩衝區的內容寫出去」（flush），大量輸出時比 \n 慢一點。一般印結果兩者都可以。
  • 沒有換行的話，下一次輸出會接在同一行後面（第三行的「第一段第二段」）。

std:: 是什麼：命名空間

std 是標準程式庫的命名空間（namespace）。命名空間像「姓氏」：標準程式庫的東西都姓 std，寫成 std::cout、std::endl、std::string。這樣你自己寫一個叫 count 的變數，也不會和別人的名字撞在一起。

很多教學會在開頭寫 using namespace std;，之後就可以省略 std::：

C++
#include <iostream>
using namespace std;    // 之後可以省略 std::

int main() {
    cout << "不用寫 std:: 了" << endl;
    return 0;
}

不用寫 std:: 了

方便，但在大型專案（例如 QuantLib）裡，大家會刻意不這樣寫：標準程式庫有上千個名字，全部「打開」容易和自己或其他程式庫的名字衝突。老師的講義都寫 std::，這份筆記也一樣。

1.6從原始碼到執行檔：建構的過程

四個階段

你按下「建置」或打 g++ main.cpp -o main 時，其實發生了好幾件事：

  1. 編輯（editor）：你把想法寫成原始碼 main.cpp。
  2. 前處理（preprocessor）：處理所有 # 開頭的指令——把 #include 的標頭檔內容整份複製貼上進來、展開 #define 巨集、刪掉註解、處理 #ifdef／#ifndef 條件。
  3. 編譯（compiler）：把前處理後的程式翻譯成組合語言，再變成目標檔（.o／.obj）。每個 .cpp 各自編譯成一個目標檔。語法錯誤在這裡被抓出來。
  4. 連結（linker）：把所有目標檔和用到的程式庫接起來，產生執行檔。如果某個函數只有宣告、找不到實作，會在這裡出錯。

最後才是執行，以及發現邏輯錯誤、回頭修改、重新建構的循環。

文字
main.cpp ──前處理──▶ 展開後的原始碼 ──編譯──▶ main.o ─┐
price.cpp ─前處理──▶ 展開後的原始碼 ──編譯──▶ price.o ─┼─連結──▶ 執行檔 main
                                         標準程式庫 ─┘

用命令列看清楚每一步

終端機
g++ -std=c++20 -Wall main.cpp -o main   # 一次完成前處理、編譯、連結
./main                                  # 執行（Windows：main.exe）

g++ -E main.cpp -o main.i               # 只做前處理（看看 #include 展開成多大）
g++ -c main.cpp -o main.o               # 只編譯成目標檔，不連結
g++ main.o -o main                      # 只做連結
  • -std=c++20：用 C++20 標準。
  • -Wall：打開常見警告（warning all），強烈建議每次都加。
  • -o main：輸出檔名（output）。

一個 #include <iostream> 展開後有多大？在這個網站的編譯環境實際算一次：前處理後的檔案超過四萬行——你寫的 5 行程式前面，被貼上了整個 iostream 程式庫的宣告。

多個檔案：宣告與定義分開

真實專案會把程式拆成很多檔案。這裡先看最簡單的例子：一個計算現值的函數放在獨立的檔案。

標頭檔只放宣告（告訴別人有這個函數、怎麼呼叫）：

C++ 檔案：finance.h
// finance.h：宣告
#ifndef FINANCE_H        // 防止同一個標頭檔被 include 兩次
#define FINANCE_H

double present_value(double cash_flow, double rate, int years);

#endif

原始檔放定義（真正的計算）：

C++ 檔案：finance.cpp
// finance.cpp：定義
#include "finance.h"
#include <cmath>

double present_value(double cash_flow, double rate, int years) {
    return cash_flow / std::pow(1 + rate, years);
}

main 只要 include 標頭檔就能使用：

C++
// main.cpp
#include <iostream>
#include "finance.h"     // 自己的標頭檔用雙引號

int main() {
    std::cout << "5 年後的 1000 元，折現率 3%，現值 = "
              << present_value(1000, 0.03, 5) << std::endl;
    return 0;
}

5 年後的 1000 元，折現率 3%，現值 = 862.609

編譯時兩個 .cpp 都要給：g++ main.cpp finance.cpp -o main。

  • #include <...> 找系統、標準程式庫的標頭檔；#include "..." 先找自己專案的標頭檔。
  • #ifndef FINANCE_H / #define FINANCE_H / #endif 叫 include guard：第一次 include 時定義 FINANCE_H，第二次再 include 時因為已經定義過，整段被跳過，避免重複宣告。老師在第 7 章的 MyTime.h 也用同樣的寫法。

如果忘了把 finance.cpp 一起編譯，編譯會通過（main.cpp 有看到宣告），但連結會失敗——找不到 present_value 的定義：

C++
#include <iostream>
double present_value(double cash_flow, double rate, int years);  // 只有宣告

int main() {
    std::cout << present_value(1000, 0.03, 5) << std::endl;
    return 0;
}

ld（連結器）: main.o: in function `main':
main.cpp:(.text+0x26): undefined reference to `present_value(double, double, int)'
collect2: error: ld returned 1 exit status

undefined reference to ... 就是連結器說的「我找不到這個函數的實作」。看到這個字眼，就去檢查：函數有沒有寫定義、檔案有沒有一起編譯、名字和參數是否完全一致。

老師建議的專案資料夾

文字

為什麼需要 CMake

檔案一多，每次都手打 g++ a.cpp b.cpp c.cpp ... -I include -o bin/app 很麻煩，換到 Windows（Visual Studio）指令又完全不同。CMake 是「產生建構檔的工具」：你只寫一份跨平台的 CMakeLists.txt，CMake 依照你的系統產生對應的建構檔——Linux／Mac 的 Makefile、Visual Studio 的專案檔，或 Ninja 的 build.ninja。Ninja 是 Google 開發、主打快速與平行化的建構工具。

最小的 CMakeLists.txt：

CMake
cmake_minimum_required(VERSION 3.10)
project(CppProject VERSION 1.0.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)                 # 使用 C++20
set(CMAKE_CXX_STANDARD_REQUIRED ON)

file(GLOB SOURCES ${CMAKE_SOURCE_DIR}/src/*.cpp)   # 收集 src 裡所有 .cpp
add_executable(MyApp ${SOURCES})                     # 產生執行檔 MyApp
target_include_directories(MyApp PRIVATE ${CMAKE_SOURCE_DIR}/include)
set_target_properties(MyApp PROPERTIES RUNTIME_OUTPUT_DIRECTORY ${CMAKE_SOURCE_DIR}/bin)

在專案資料夾執行：

終端機
cmake -S . -B build -G Ninja    # 讀 CMakeLists.txt，在 build 資料夾產生 Ninja 建構檔
cmake --build build             # 真正編譯、連結
./bin/MyApp                     # 執行

老師講義的完整版本還會加入 QuantLib：用 add_subdirectory() 把 external/QuantLib-1.37 一起建構，再用 target_link_libraries(MyApp PRIVATE ql_library) 把 QuantLib 連結進來（第一次建構 QuantLib 要花不少時間，是正常的）。

1.8第一個金融小程式：複利與現值

把這一章學到的組起來，做一個有用的小工具：給定本金、年利率、年數，計算到期金額與「到期拿 1,000 元」的現值。

C++
#include <iostream>
#include <iomanip>
#include <cmath>          // std::pow 次方

int main() {
    double principal = 100000;   // 本金
    double rate = 0.03;          // 年利率 3%
    int years = 10;              // 10 年

    double future_value = principal * std::pow(1 + rate, years);   // FV = P(1+r)^n
    double pv_of_1000 = 1000 / std::pow(1 + rate, years);          // PV = F/(1+r)^n

    std::cout << std::fixed << std::setprecision(2);
    std::cout << "本金 " << principal << " 元，年利率 " << rate * 100 << "%，" << years << " 年\n";
    std::cout << "到期本利和：" << future_value << " 元\n";
    std::cout << "10 年後的 1000 元，現值：" << pv_of_1000 << " 元\n";
    return 0;
}

本金 100000.00 元，年利率 3.00%，10 年
到期本利和：134391.64 元
10 年後的 1000 元，現值：744.09 元
  • #include <cmath> 提供數學函數，std::pow(a, b) 是 \(a^b\)（C++ 沒有 ^ 次方運算子！^ 在 C++ 是位元運算）。
  • 公式：終值 \(FV=P(1+r)^n\)、現值 \(PV=\dfrac{F}{(1+r)^n}\)。\(P\) 是今天投入的本金，\(F\) 是未來收到的金額，\(r\) 是每期利率，\(n\) 是期數。終值是「錢放 \(n\) 期、每期乘一次 \((1+r)\)」；現值反過來除回去，回答「未來的 \(F\) 元今天值多少」。
  • double 是「有小數的數字」，int 是整數——下一章詳細介紹各種型態。

換個寫法：每年印一次（預告迴圈）

C++
#include <iostream>
#include <iomanip>

int main() {
    double balance = 100000;
    double rate = 0.03;
    std::cout << std::fixed << std::setprecision(2);
    for (int year = 1; year <= 5; year++) {
        balance = balance * (1 + rate);          // 每年乘上 (1 + r)
        std::cout << "第 " << year << " 年底：" << balance << "\n";
    }
    return 0;
}

第 1 年底：103000.00
第 2 年底：106090.00
第 3 年底：109272.70
第 4 年底：112550.88
第 5 年底：115927.41

用迴圈一年一年乘上去，第 5 年的結果會和 principal * std::pow(1.03, 5) 一樣。同一個問題有「公式一步算出」和「模擬每一期」兩種寫法——後者雖然慢，但很容易擴充成「每年利率不同」「中途提領」等真實情況，這種「逐期模擬」的想法在金融計算（例如二元樹、蒙地卡羅）到處都是。

換個角度想再多試幾個想法
  • 把年數改成 30、利率改成 0.07，看看「72 法則」（翻倍年數 ≈ 72 / 利率%）準不準。
  • 改成每月複利：月利率 = 年利率 / 12，期數 = 年數 × 12。
  • 用 ^ 代替 std::pow 看看會發生什麼（結果不是你想的次方！）。

Q2

寫程式｜中年金終值

每年年底存 10,000 元，年利率 2%，存 20 年。用 for 迴圈一年一年累加，印出第 20 年底的帳戶餘額（2 位小數），並和公式 \(FV=C\dfrac{(1+r)^n-1}{r}\) 的結果比較（\(C\) 是每年存入的金額；這個公式就是把 \(n\) 筆存款各自滾到最後一年再加總的等比級數和，和迴圈一年一年加的結果應該一樣）。

答案
C++
#include <iostream>
#include <iomanip>
#include <cmath>

int main() {
    double c = 10000, r = 0.02;
    int n = 20;
    double balance = 0;
    for (int year = 1; year <= n; year++) {
        balance = balance * (1 + r) + c;   // 先滾一年利息，再存入這一年的 10000
    }
    double formula = c * (std::pow(1 + r, n) - 1) / r;
    std::cout << std::fixed << std::setprecision(2);
    std::cout << "迴圈：" << balance << "\n公式：" << formula << "\n";
    return 0;
}

迴圈：242973.70
公式：242973.70

解析

每年的變化是「舊餘額 × (1+r) + 當年存入」；20 次之後和年金終值公式完全一致。用迴圈驗證公式（或用公式驗證迴圈）是寫金融程式的好習慣。

1.9本章小結

  • C++ 是以 C 為基礎的編譯式、強型別語言，速度快，是金融計算核心（QuantLib）的主要語言；C++11 以後稱為現代 C++。
  • 程式從 main 開始執行；#include 引入程式庫；敘述以 ; 結尾；{ } 圍出區塊；區分大小寫。
  • 輸出：std::cout << ... << std::endl;；\n、\t 跳脫字元；<iomanip> 的 fixed、setprecision、setw 控制格式。
  • 建構過程：前處理（展開 #include、#define）→ 編譯（每個 .cpp 變成目標檔，抓語法錯誤）→ 連結（接成執行檔，undefined reference 是連結錯誤）。
  • 多檔案：宣告放 .h（加 include guard），定義放 .cpp；專案大了用 CMake（＋Ninja）管理建構。
  • 編譯錯誤先看第一個 error 和行號；能執行但結果不對是邏輯錯誤，要自己驗算。
