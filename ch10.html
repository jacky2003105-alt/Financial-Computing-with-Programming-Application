10.2NPV() 背後發生的事

在 QuantLib 中，bond.NPV() 的呼叫順序大致是：

文字
Bond::NPV()                     ← 使用者呼叫：只是「讀取結果」的介面
  └─ LazyObject::calculate()    ← 檢查結果是否還有效
       └─ performCalculations() ← 真的要算時才算
            └─ PricingEngine::calculate()   ← 演算法本體（可替換）

老師強調：重點不是流程，而是責任切分。

問題：市場資料變了，價格要不要重算？

一張債券的價格取決於殖利率曲線、評價日、利率報價……

  • 同一個價格可能被上萬次呼叫（風控、報表、交易、監理各自呼叫）——每次都重算太浪費。
  • 市場資料不一定真的有變——但只要有一個變了，舊的價格就不能用。
  • 重算的成本可能很高（蒙地卡羅、樹狀模型）。

所以問題變成：怎麼做到「只在需要時才算，而且永遠算對」？

答案：觀察者模式 + 快取旗標

觀察者模式（Observer Pattern）的兩個角色：

角色 意思 QuantLib 實例
Observable（被觀察者） 「我會變，而且有人在乎我變不變」 報價 Quote、殖利率曲線、評價日
Observer（觀察者） 「只要你變了，我就要做事」 Instrument、LazyObject
通知 Observable 呼叫 notifyObservers()
反應 Observer 的 update() 被呼叫

關鍵是方向：不是債券去問資料「你有沒有變」，而是資料主動說「我變了」。

LazyObject = Observer + Observable + 快取控制：

  • 有一個 mutable bool calculated_：true 表示目前的結果可信，false 表示過期了。
  • update()（收到通知時）只做一件事：標記 calculated_ = false，不計算。
  • calculate() 是「快取閘門＋有效性閘門」：結果有效就直接用；過期了才呼叫 performCalculations()。
  • NPV() 只負責「確保結果有效」，然後回傳——不把計算邏輯塞在 getter 裡。

10.3自己寫一個迷你 QuantLib

把整學期的語法組合起來：智慧指標、抽象類別、虛函數與 override、mutable、const、多重繼承與虛擬繼承、例外安全、lambda。

C++
#include <iostream>
#include <iomanip>
#include <vector>
#include <memory>
#include <algorithm>
#include <cmath>

// ===== 觀察者模式 =====
class Observer {
public:
    virtual void update() = 0;
    virtual ~Observer() = default;
};

class Observable {
public:
    void registerObserver(Observer *o) { observers_.push_back(o); }
    void unregisterObserver(Observer *o) {
        observers_.erase(std::remove(observers_.begin(), observers_.end(), o), observers_.end());
    }
    void notifyObservers() {
        for (Observer *o : observers_) o->update();
    }
    virtual ~Observable() = default;
private:
    std::vector<Observer*> observers_;
};

// ===== 市場報價：會變的東西 =====
class SimpleQuote : public Observable {
public:
    explicit SimpleQuote(double v) : value_(v) {}
    double value() const { return value_; }
    void setValue(double v) {
        if (v != value_) {                  // 真的有變才通知
            value_ = v;
            std::cout << "  [Quote] 報價變成 " << v << "，通知觀察者\n";
            notifyObservers();
        }
    }
private:
    double value_;
};

// ===== LazyObject：觀察者 + 被觀察者 + 快取 =====
class LazyObject : public virtual Observable, public virtual Observer {
public:
    void update() override {                // 只標記，不計算
        if (calculated_) {
            calculated_ = false;
            notifyObservers();              // 也通知依賴「我」的人
        }
    }
protected:
    void calculate() const {
        if (!calculated_) {
            calculated_ = true;             // 先設 true，避免遞迴
            try {
                performCalculations();
            } catch (...) {
                calculated_ = false;        // 算失敗：回復狀態，例外往上丟
                throw;
            }
        }
    }
    virtual void performCalculations() const = 0;
    mutable bool calculated_ = false;       // const 的 calculate() 也要能改它
};

// ===== 殖利率曲線：觀察報價，本身也被觀察 =====
class FlatCurve : public LazyObject {
public:
    explicit FlatCurve(std::shared_ptr<SimpleQuote> rate) : rate_(std::move(rate)) {
        rate_->registerObserver(this);
    }
    ~FlatCurve() override { rate_->unregisterObserver(this); }
    double discount(double t) const { return std::exp(-rate_->value() * t); }
    void update() override {                // 曲線本身沒有快取，直接轉發通知
        notifyObservers();
    }
protected:
    void performCalculations() const override {}
private:
    std::shared_ptr<SimpleQuote> rate_;
};

// ===== 商品：只負責「保證結果有效」=====
class Instrument : public LazyObject {
public:
    double NPV() const {
        calculate();                        // 確保結果是最新的
        return npv_;
    }
protected:
    mutable double npv_ = 0.0;
};

class FixedRateBond : public Instrument {
public:
    FixedRateBond(double face, double coupon, int years, std::shared_ptr<FlatCurve> curve)
        : face_(face), coupon_(coupon), years_(years), curve_(std::move(curve)) {
        curve_->registerObserver(this);
    }
    ~FixedRateBond() override { curve_->unregisterObserver(this); }
    int calcCount() const { return count_; }
protected:
    void performCalculations() const override {      // 真正的金融計算
        ++count_;
        double v = 0;
        for (int t = 1; t <= years_; ++t) v += face_ * coupon_ * curve_->discount(t);
        npv_ = v + face_ * curve_->discount(years_);
    }
private:
    double face_, coupon_;
    int years_;
    std::shared_ptr<FlatCurve> curve_;
    mutable int count_ = 0;
};

int main() {
    auto rate  = std::make_shared<SimpleQuote>(0.02);
    auto curve = std::make_shared<FlatCurve>(rate);
    FixedRateBond bond(100, 0.03, 5, curve);

    std::cout << std::fixed << std::setprecision(4);
    for (int i = 0; i < 3; ++i)                       // 呼叫很多次……
        std::cout << "NPV = " << bond.NPV() << "\n";
    std::cout << "實際計算次數：" << bond.calcCount() << "\n\n";

    rate->setValue(0.025);                            // 市場資料變動
    std::cout << "（此時還沒有重算，計算次數仍是 " << bond.calcCount() << "）\n";
    std::cout << "NPV = " << bond.NPV() << "\n";      // 下次讀取才重算
    std::cout << "NPV = " << bond.NPV() << "\n";
    std::cout << "實際計算次數：" << bond.calcCount() << "\n\n";

    rate->setValue(0.025);                            // 沒有真的變：不會通知
    std::cout << "NPV = " << bond.NPV() << "，計算次數：" << bond.calcCount() << "\n";
    return 0;
}

對照執行結果看：

  • 效率：資料沒變時，NPV() 呼叫 3 次只真的計算 1 次。
  • 正確性：報價一變，通知一路傳下去（Quote → Curve → Bond），債券把自己標記為過期；下一次讀取時一定重算，絕不會用到過期的結果。
  • 延遲：通知當下並不計算——如果報價在一秒內變了 100 次但沒人讀價格，就一次都不用算。

用到的語法回顧：

語法 在哪裡 章節
抽象類別、純虛函數 Observer::update、performCalculations 8.4
override 每個覆寫 8.2
虛擬繼承 LazyObject : public virtual Observable, public virtual Observer 8.7
mutable calculated_、npv_：const 的 NPV() 也能更新快取 7.4
const 成員函數 NPV()、discount() 不改變「邏輯狀態」 7.4
shared_ptr 報價與曲線被多個物件共用 6.5
虛解構函數 所有父類別；解構時取消註冊 8.4、7.7
例外安全 calculate() 的 try/catch/rethrow 4.10
std::remove + erase 從觀察者清單移除 3.7
換個角度想為什麼 LazyObject 要用虛擬繼承？

老師講義指出：Instrument 可能同時是 Observable 和 Observer；PricingEngine 也是。當一個類別經由多條路徑繼承 Observable 時，如果沒有虛擬繼承，物件裡會有好幾份觀察者清單，通知會漏掉。虛擬繼承確保整個物件只有一份 Observable、一份 Observer（第 8.7 節的菱形繼承）。

Q1

選擇｜中update 的責任

在 LazyObject 的設計中，update() 被呼叫時應該做什麼？

  1. (A)只標記目前的結果已經過期
  2. (B)立刻重新計算一次最新的價格
  3. (C)把這個物件從記憶體中刪除
  4. (D)把最新算好的 NPV 回傳出去
答案 (A)

只標記目前的結果已經過期

解析

update 只負責把 calculated_ 設為 false、標記狀態；真正的計算延到下次有人呼叫 NPV() 時才做，避免市場資料頻繁變動時做大量沒人需要的計算。

Q2

簡答｜中mutable 的必要

為什麼 calculated_ 與 npv_ 要宣告成 mutable？

答案

NPV() 是「讀取結果」的介面，邏輯上不改變物件的狀態，所以宣告為 const 成員函數，好讓 const 物件或 const 參考也能呼叫。但 NPV() 內部可能需要重新計算並更新快取（npv_）與旗標（calculated_），const 成員函數本來不能修改成員變數，所以這兩個成員要宣告為 mutable：它們屬於快取這種「不影響物件邏輯狀態」的內部細節。

Q3

寫程式｜難多一個觀察者

在上面的程式中，新增一張 10 年期、票面利率 2% 的債券，共用同一條曲線；報價從 2% 改成 3% 後，印出兩張債券的 NPV 與各自的計算次數，驗證一次報價變動會同時讓兩張債券過期。（main 以外的程式不需修改，只要寫出 main 的內容。）

答案
C++
int main() {
    auto rate  = std::make_shared<SimpleQuote>(0.02);
    auto curve = std::make_shared<FlatCurve>(rate);
    FixedRateBond b5(100, 0.03, 5, curve);
    FixedRateBond b10(100, 0.02, 10, curve);
    std::cout << b5.NPV() << " " << b10.NPV() << "\n";
    rate->setValue(0.03);
    std::cout << b5.NPV() << " " << b10.NPV() << "\n";
    std::cout << b5.calcCount() << " " << b10.calcCount() << "\n";   // 都是 2
}

解析

兩張債券都向曲線註冊為觀察者，曲線再向報價註冊；報價變動時曲線轉發通知，兩張債券都被標記為過期，各自在下次讀取時重算一次。

10.4再看一次：二項樹定價（迴圈版）

第 5 章說過，二項樹用遞迴寫很直觀但很慢。實務上用一個 vector 從到期日往回推（backward induction），也正好是一個好的「策略引擎」候選：

C++
#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>
#include <functional>

double binomial(double S, double K, double r, double sigma, double T, int N,
                const std::function<double(double)> &payoff, bool american) {
    double dt = T / N;
    double u = std::exp(sigma * std::sqrt(dt)), d = 1 / u;
    double p = (std::exp(r * dt) - d) / (u - d);           // 風險中立機率
    double disc = std::exp(-r * dt);

    std::vector<double> v(N + 1);
    for (int j = 0; j <= N; ++j)                            // 到期日的報酬
        v[j] = payoff(S * std::pow(u, j) * std::pow(d, N - j));

    for (int i = N - 1; i >= 0; --i) {                      // 往回推
        for (int j = 0; j <= i; ++j) {
            double cont = disc * (p * v[j + 1] + (1 - p) * v[j]);
            double exercise = payoff(S * std::pow(u, j) * std::pow(d, i - j));
            v[j] = american ? std::max(cont, exercise) : cont;
        }
    }
    return v[0];
}

int main() {
    double S = 100, K = 100, r = 0.03, sigma = 0.25, T = 1;
    auto put = [K](double s) { return std::max(K - s, 0.0); };
    auto call = [K](double s) { return std::max(s - K, 0.0); };
    for (int N : {10, 100, 1000}) {
        std::cout << "N = " << N
                  << "  歐式買權 " << binomial(S, K, r, sigma, T, N, call, false)
                  << "  歐式賣權 " << binomial(S, K, r, sigma, T, N, put, false)
                  << "  美式賣權 " << binomial(S, K, r, sigma, T, N, put, true) << "\n";
    }
    return 0;
}

  • payoff 用 std::function 傳入：同一棵樹可以定價買權、賣權、數位選擇權……

10.6本章小結

  • 這門課的主線：C++ 語言 → 物件模型 → 金融系統架構。
  • Instrument 不知道怎麼算，PricingEngine 才是演算法；override 是模型的插槽。
  • 每個關鍵字都對應一個工程需求：virtual／override（可替換、防寫錯）、explicit（防誤轉型）、= delete（強制必要參數）、const／mutable（狀態與快取）、static（共用）、friend（緊密合作）。
  • 觀察者模式：資料主動通知（notifyObservers() → update()），而不是物件不斷詢問。
  • LazyObject：update() 只標記過期；calculate() 是快取閘門與有效性閘門；NPV() 只保證結果有效。目標是「只在需要時才算，而且永遠算對」。
