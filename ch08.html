8.1繼承：子類別沿用父類別

基本語法與建構順序

C++
#include <iostream>

class Human {                                   // 父類別（基礎類別，base class）
public:
    Human() { std::cout << "執行 Human::Human()\n"; }
    Human(int age) : m_Age(age) { std::cout << "執行 Human::Human(int)\n"; }
    ~Human() { std::cout << "執行 Human::~Human()\n"; }
    int m_Age = 0;
    void eat() { std::cout << "Human 吃飯\n"; }
};

class Men : public Human {                      // 子類別（衍生類別，derived class）
public:
    Men() { std::cout << "執行 Men::Men()\n"; }
    Men(int age) : Human(age) { std::cout << "執行 Men::Men(int)\n"; }   // 在初始化列表呼叫父類別建構函數
    ~Men() { std::cout << "執行 Men::~Men()\n"; }
    void shave() { std::cout << "Men 刮鬍子\n"; }
};

int main() {
    {
        Men a;
        a.eat();                                // 繼承來的成員函數
        a.shave();                              // 自己新增的
        a.m_Age = 30;                           // 繼承來的成員變數
    }
    std::cout << "----\n";
    Men b(45);
    std::cout << "b 的年齡 " << b.m_Age << "\n";
    return 0;
}

  • 語法：class 子類別 : 繼承方式 父類別 { ... };，繼承方式通常是 public。
  • 子類別自動擁有父類別的成員，只需要寫自己獨有的部分——這就是繼承減少重複程式碼的方式。子類別可以：使用父類別允許存取的成員、新增自己的成員、覆寫父類別的虛函數（8.2 節）。
  • 建構順序：先建構父類別部分，再建構子類別部分（先打地基再蓋房子）；解構順序相反：先子類別、再父類別。
  • 老師上課補充的細節：建立子類別物件時，先初始化父類別的資料成員、執行父類別建構函數的本體，再初始化子類別的資料成員、執行子類別建構函數的本體；銷毀時完全相反。
  • 要指定呼叫父類別的哪個建構函數，就在子類別建構函數的初始化列表寫 父類別名(參數)；沒寫的話，自動呼叫父類別的預設建構函數。

存取等級：public、protected、private

C++
#include <iostream>

class Base {
public:
    int publicValue = 10;
protected:
    int protectedValue = 20;      // 自己與「子類別」可以用，外界不行
private:
    int privateValue = 30;        // 只有自己可以用
public:
    int get_private() const { return privateValue; }   // 透過介面讓子類別間接取得
};

class Derived : public Base {
public:
    void modify() {
        publicValue = 100;        // 可以
        protectedValue = 200;     // 可以：子類別看得到 protected
        // privateValue = 300;    // 錯誤：子類別也看不到父類別的 private
        std::cout << "private 值（透過介面）= " << get_private() << "\n";
    }
};

int main() {
    Derived obj;
    obj.modify();
    obj.publicValue = 1;          // 可以
    // obj.protectedValue = 2;    // 錯誤：外界看不到 protected
    std::cout << obj.publicValue << "\n";
    return 0;
}

private 值（透過介面）= 30

父類別的 private 成員仍然存在於子類別物件裡（佔記憶體），只是子類別不能直接碰，要透過父類別提供的函數。

繼承方式

「繼承方式」和「成員存取等級」是兩件事：繼承方式決定父類別的成員在子類別中變成什麼等級：

父類別成員 public 繼承後 protected 繼承後 private 繼承後
public public protected private
protected protected protected private
private 不能直接存取 不能直接存取 不能直接存取
  • public 繼承：等級不變，表達「子類別是一種父類別」（is-a）——FixedRateBond 是一種 Bond。幾乎所有情況都用它。
  • 不寫繼承方式時：class 預設 private 繼承、struct 預設 public 繼承。
老師上課怎麼說public 有兩種意思

老師提醒不要混淆：public 這個字有兩種用法——一種談的是存取等級（成員誰看得到），一種談的是繼承等級（class Men : public Human）。父類別的 private 是封裝程度最高的，外界看不到、也不給小孩直接用，所以不必討論「public 繼承後它在子類別變成什麼等級」——它根本存取不到。想讓子類別用、又不想讓外界用的，就放 protected。

C++
class Human {
public:
    int m_Age = 0;
};

class Men : protected Human {};    // protected 繼承：m_Age 在 Men 中變成 protected

int main() {
    Men men;
    men.m_Age = 10;                // 錯誤：外界無法存取
    return 0;
}

8.2覆寫、虛函數與多型

父類別指標可以指向子類別物件

一個 FixedRateBond 是一種 Bond，所以 C++ 允許用父類別的指標或參考指向子類別物件（向上轉型，upcasting）：

C++
#include <iostream>

class Instrument {
public:
    void describe() const { std::cout << "一般金融商品\n"; }      // 沒有 virtual
};

class Stock : public Instrument {
public:
    void describe() const { std::cout << "股票\n"; }
    void dividend() const { std::cout << "發放股利\n"; }
};

int main() {
    Stock s;
    Instrument *p = &s;           // 父類別指標指向子類別物件
    Instrument &r = s;
    s.describe();                 // 股票
    p->describe();                // 一般金融商品！
    r.describe();                 // 一般金融商品！
    // p->dividend();             // 錯誤：透過父類別指標看不到子類別特有的函數
    return 0;
}

沒有 virtual 時，呼叫哪個版本是看指標的型態（編譯期就決定了，靜態綁定），而不是看物件實際是什麼。

virtual：依物件的真實型態決定

在父類別的函數前加上 virtual，它就成為虛函數；子類別提供同樣簽名的版本，就是覆寫（override）。透過父類別指標或參考呼叫時，會在執行期依照物件的實際型態決定執行哪個版本——動態綁定：

C++
#include <iostream>
#include <iomanip>
#include <vector>
#include <memory>
#include <cmath>

class Instrument {
public:
    virtual double npv() const { return 0.0; }           // 虛函數
    virtual const char *name() const { return "Instrument"; }
    virtual ~Instrument() = default;                    // 虛解構函數（8.4 節）
};

class ZeroBond : public Instrument {
public:
    ZeroBond(double face, double r, double T) : face_(face), r_(r), T_(T) {}
    double npv() const override { return face_ * std::exp(-r_ * T_); }   // 覆寫
    const char *name() const override { return "ZeroBond"; }
private:
    double face_, r_, T_;
};

class Cash : public Instrument {
public:
    explicit Cash(double amt) : amt_(amt) {}
    double npv() const override { return amt_; }
    const char *name() const override { return "Cash"; }
private:
    double amt_;
};

int main() {
    std::vector<std::unique_ptr<Instrument>> book;       // 一個容器裝各種商品
    book.push_back(std::make_unique<ZeroBond>(1'000'000, 0.02, 3));
    book.push_back(std::make_unique<Cash>(250'000));
    book.push_back(std::make_unique<ZeroBond>(500'000, 0.025, 10));

    double total = 0;
    std::cout << std::fixed << std::setprecision(0);
    for (const auto &ins : book) {                       // 同一行程式碼……
        std::cout << ins->name() << "：" << ins->npv() << "\n";   // ……依實際型態呼叫不同版本
        total += ins->npv();
    }
    std::cout << "部位總值 = " << total << "\n";
    return 0;
}

ZeroBond：941765
Cash：250000
ZeroBond：389400
部位總值 = 1581165

這就是多型（polymorphism）：同一個介面（npv()），作用在不同物件上產生不同行為。投資組合的程式碼只需要知道「每個東西都是 Instrument、都能算 npv」，新增一種商品時，加一個子類別就好，計算總值的迴圈一行都不用改。

老師上課怎麼說只要來自同一個父親

老師的總結：只要子類別都來自同一個父類別、父類別定義好虛函數、子類別各自覆寫，程式在執行過程中讓父類別指標放入不同子類別的指標值，「程式不用做任何修改」就會呼叫到各自的版本——這在 QuantLib 裡「非常多」。反過來，子類別的指標變數不能存放父類別的指標值，這是不行的。

override 關鍵字：讓編譯器幫你檢查

覆寫的條件很嚴格：函數名稱、參數型態與順序、const 等修飾都要完全相同，父類別的函數必須是 virtual。少一個 const 就不是覆寫，而是另一個新函數——而且編譯器不會說什麼。C++11 的 override 讓編譯器檢查「這個函數真的覆寫了父類別的某個虛函數」：

C++
class Base {
public:
    virtual void display() const {}
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void display() override {}       // 錯誤：少了 const，並沒有覆寫任何函數
};

int main() { return 0; }

main.cpp:9:10: error: ‘void Derived::display()’ marked ‘override’, but does not override
    9 |     void display() override {}       // 錯誤：少了 const，並沒有覆寫任何函數
      |          ^~~~~~~
main.cpp:3:18: warning: ‘virtual void Base::display() const’ was hidden [-Woverloaded-virtual=]
    3 |     virtual void display() const {}
      |                  ^~~~~~~
main.cpp:9:10: note:   by ‘void Derived::display()’
    9 |     void display() override {}       // 錯誤：少了 const，並沒有覆寫任何函數
      |          ^~~~~~~
  • 子類別覆寫時不必再寫 virtual（虛函數的性質會被繼承），但建議一律寫 override。
  • override 本身不會「啟動」多型，它只是檢查；是父類別的 virtual 讓多型成立。
  • 例外：回傳型態可以是協變的——父類別回傳 Base*（或 Base&），子類別覆寫時可以回傳 Derived*（或 Derived&）。以值回傳時不行。
老師上課怎麼說少一個 const 就不是覆寫

老師在課堂上實際示範：子類別的函數名稱一樣、小括號裡的參數列表也一樣（都是空的），「但是還是不能做覆寫」——因為父類別的版本有加 const，子類別也要加。老師也把 virtual 與 override 拿掉再編譯：程式照樣編譯得過，但已經沒有多型了，錯誤要到執行時看結果才會發現。加上 C++11 的 override，這種錯誤就在編譯期被抓出來——它的好處就是「多一個檢查」；能不能覆寫，決定權在父類別有沒有 virtual、簽名是否相符，而不是 override 這個字有沒有寫。

虛函數怎麼做到的：vtable

老師講義說明了背後的機制：每個有虛函數的類別都有一張虛函數表（vtable），存放該類別各個虛函數的位址；每個物件裡藏著一個虛指標（vptr）指向自己類別的那張表。呼叫 p->npv() 時，程式透過 vptr 找到表、在表中查到實際要執行的函數。代價是每個物件多一個指標的大小、每次呼叫多一次查表：

C++
#include <iostream>

struct Plain   { double x; void f() {} };
struct Virtual { double x; virtual void f() {} virtual ~Virtual() = default; };

int main() {
    std::cout << "沒有虛函數：" << sizeof(Plain) << " bytes\n";
    std::cout << "有虛函數：  " << sizeof(Virtual) << " bytes（多了 vptr）\n";
    return 0;
}

沒有虛函數：8 bytes
有虛函數：  16 bytes（多了 vptr）

向下轉型：dynamic_cast

透過父類別指標看不到子類別特有的函數。如果真的需要，可以用 dynamic_cast 做執行期檢查的向下轉型——轉型失敗時（物件其實不是那個子類別）指標版回傳 nullptr：

C++
#include <iostream>
#include <memory>
#include <vector>

class Instrument { public: virtual ~Instrument() = default; };
class Stock : public Instrument {
public:
    double dividend_yield() const { return 0.035; }
};
class Bond : public Instrument {};

int main() {
    std::vector<std::unique_ptr<Instrument>> v;
    v.push_back(std::make_unique<Stock>());
    v.push_back(std::make_unique<Bond>());
    for (const auto &p : v) {
        if (auto *s = dynamic_cast<Stock*>(p.get())) {     // 是 Stock 才轉得成功
            std::cout << "股票，殖利率 " << s->dividend_yield() << "\n";
        } else {
            std::cout << "不是股票\n";
        }
    }
    return 0;
}

股票，殖利率 0.035
不是股票

大量使用 dynamic_cast 通常表示設計可以改進——如果每種商品都需要某個功能，應該把它做成父類別的虛函數。

老師上課強調多型與 vtable

老師強調「多型很重要，它是物件導向的核心功能之一」，並說明為什麼一定要用父類別指標：可以用父類別的指標指向所有子類別的物件，只要父類別定義好介面（虛函數）、子類別適當覆寫，就能做到多型。反過來，子類別的指標不能指向父類別的物件，「這是最基本的觀念」。講到 vtable 時，老師說它看起來像一張表，在記憶體中其實就是一個函數指標陣列；程式載入記憶體時每個函數都有自己的位址，子類別覆寫後，呼叫時就到表中找到適當的版本。教科書會談這些內部細節，要知道 vtable 與 vptr 各自的角色。

Q1

預測輸出｜中virtual 的有無

下面程式印出什麼？

C++
#include <iostream>
struct Base {
    void a() { std::cout << "Ba "; }
    virtual void b() { std::cout << "Bb "; }
    virtual ~Base() = default;
};
struct Der : Base {
    void a() { std::cout << "Da "; }
    void b() override { std::cout << "Db "; }
};
int main() {
    Der d;
    Base &r = d;
    r.a(); r.b(); d.a(); d.b();

答案

解析

a 不是虛函數，透過 Base& 呼叫時看參考的型態，執行 Base::a；b 是虛函數，依物件的實際型態執行 Der::b。直接用 d 呼叫則都是 Der 的版本。

Q3

簡答｜中多型的好處

投資組合程式用 std::vector<std::unique_ptr<Instrument>> 存放各種商品，並用迴圈呼叫 ins->npv() 加總。若之後要新增「利率交換」商品，需要修改哪些程式碼？這體現了多型的什麼好處？

答案

只需要新增一個繼承 Instrument 並覆寫 npv()（以及其他虛函數）的 Swap 子類別，再把它放進容器即可；加總市值的迴圈、報表等使用 Instrument 介面的程式碼完全不需修改。這體現了多型「對擴充開放、對修改封閉」的好處：使用端只依賴共同的介面，新的實作可以直接插入。

8.3覆寫、遮蔽與重載

遮蔽：同名就會蓋掉

子類別定義了和父類別同名的函數，但不構成覆寫（父類別不是 virtual、或參數不同、或 const 不同）時，子類別的版本會遮蔽（hide）父類別所有同名的函數：

C++
#include <iostream>

class Base {
public:
    void f() { std::cout << "Base::f()\n"; }
    void f(int) { std::cout << "Base::f(int)\n"; }
};

class Derived : public Base {
public:
    void f(double) { std::cout << "Derived::f(double)\n"; }   // 遮蔽了 Base 的兩個 f
};

int main() {
    Derived d;
    d.f(3.14);     // Derived::f(double)
    d.f();         // 錯誤：Base::f() 被遮蔽了，名稱查找在 Derived 就停了
    return 0;
}

   17 |     d.f();         // 錯誤：Base::f() 被遮蔽了，名稱查找在 Derived 就停了
      |     ~~~^~
main.cpp:11:10: note: candidate: ‘void Derived::f(double)’
   11 |     void f(double) { std::cout << "Derived::f(double)\n"; }   // 遮蔽了 Base 的兩個 f
      |          ^

要用父類別的版本，可以明確指定 d.Base::f();，或在子類別中寫 using Base::f; 把父類別的同名函數「引進來」一起參與重載：

C++
#include <iostream>

class Base {
public:
    void f() { std::cout << "Base::f()\n"; }
    void f(int) { std::cout << "Base::f(int)\n"; }
};

class Derived : public Base {
public:
    using Base::f;                                             // 把 Base 的 f 引入
    void f(double) { std::cout << "Derived::f(double)\n"; }
};

int main() {
    Derived d;
    d.f();         // Base::f()
    d.f(1);        // Base::f(int)：int 精確匹配
    d.f(1.5);      // Derived::f(double)
    d.Base::f(2);  // 明確指定父類別版本
    return 0;
}

三者比較

重載 overloading 覆寫 overriding 遮蔽 hiding
發生在 同一個作用域 父子類別之間 父子類別之間
條件 同名、參數不同 父類別 virtual、簽名完全相同 同名但不構成覆寫
何時決定 編譯期 執行期（依物件實際型態） 編譯期
目的 同一功能的不同參數版本 同一介面、不同實作（多型） 子類別提供新版本（常是無意的）
老師上課怎麼說遮蔽是誰遮誰？

老師：在繼承關係中，當然是子類別遮蔽父類別——而且「只要名字一樣就可以了」，不管回傳型態、參數是否相同。課堂上的例子：父類別明明有一個接受 int 的 display，透過子類別物件卻呼叫不到，「為什麼？遮蔽掉了」。但仍然「有辦法跨過去」：寫 obj.Base::display(...)，或在子類別的 public 區寫 using Base::display;——這個 using 並沒有多創造出新的函數，只是把父類別的宣告引進來。

老師講義整理的函數呼叫流程：名稱查找（決定看得到哪些同名函數，遮蔽在這裡發生）→ 重載決議（依參數選版本）→ 虛函數派發（若選中的是虛函數，執行期依物件型態決定）。

老師上課強調覆寫、遮蔽、重載

老師上課回顧時說：上週比較了覆寫（override）、遮蔽（hiding）、重載（overload）這三個機制，「這個是很重要的，這三個觀念要非常清楚」，作業裡也有一題在問這些問題。

常見錯誤最常見的錯誤

以為「子類別寫了一個同名函數」就是覆寫。只要父類別沒寫 virtual，或簽名差了一點（例如少了 const），就只是遮蔽，透過父類別指標呼叫時永遠執行父類別的版本。覆寫一律加 override，讓編譯器替你檢查。

選擇｜中遮蔽

父類別有 void calc(int); 與 void calc(int, int);，子類別只定義了 void calc(double);，則 child.calc(1, 2); 會？

  1. (A)呼叫父類別的 calc(int, int)
  2. (B)執行期才決定呼叫哪一個
  3. (C)呼叫子類別的 calc(double)

8.4抽象類別與虛解構函數

純虛函數與抽象類別

有些父類別只是用來定義介面，本身沒辦法給出合理的實作——「一般的金融商品」要怎麼算價格？這時可以把虛函數寫成 = 0，叫純虛函數；含有純虛函數的類別是抽象類別，不能建立物件，只能當父類別：

C++
#include <iostream>
#include <cmath>
#include <memory>
#include <vector>

class Option {                                     // 抽象類別：定義「選擇權」的介面
public:
    Option(double K, double T) : K_(K), T_(T) {}
    virtual double payoff(double ST) const = 0;    // 純虛函數：每種選擇權自己定義
    virtual const char *type() const = 0;
    double strike() const { return K_; }
    virtual ~Option() = default;
protected:
    double K_, T_;
};

class Call : public Option {
public:
    using Option::Option;                          // 沿用父類別的建構函數（C++11）
    double payoff(double ST) const override { return std::max(ST - K_, 0.0); }
    const char *type() const override { return "Call"; }
};

class Put : public Option {
public:
    using Option::Option;
    double payoff(double ST) const override { return std::max(K_ - ST, 0.0); }
    const char *type() const override { return "Put"; }
};

class Digital : public Option {
public:
    using Option::Option;
    double payoff(double ST) const override { return ST > K_ ? 1.0 : 0.0; }
    const char *type() const override { return "Digital"; }
};

int main() {
    // Option o(100, 1);                           // 錯誤：抽象類別不能實例化
    std::vector<std::unique_ptr<Option>> opts;
    opts.push_back(std::make_unique<Call>(100, 1));
    opts.push_back(std::make_unique<Put>(100, 1));
    opts.push_back(std::make_unique<Digital>(105, 1));
    for (double ST : {90.0, 100.0, 110.0}) {
        std::cout << "ST = " << ST << "：";
        for (const auto &o : opts) std::cout << o->type() << "(" << o->strike() << ")=" << o->payoff(ST) << "  ";
        std::cout << "\n";
    }
    return 0;
}

ST = 90：Call(100)=0  Put(100)=10  Digital(105)=0  
ST = 100：Call(100)=0  Put(100)=0  Digital(105)=0  
ST = 110：Call(100)=10  Put(100)=0  Digital(105)=1
  • 抽象類別的用途：規定所有子類別都必須提供某些功能（不實作所有純虛函數的子類別，自己也還是抽象類別）；使用端只依賴抽象介面，不必知道具體是哪種子類別。
  • QuantLib 的 Instrument 就是抽象類別：它定義了 NPV()、isExpired() 等介面，Bond、VanillaOption、Swap 各自實作。
老師上課怎麼說虛函數 vs 純虛函數：一定要覆寫嗎？

老師上課問：父類別有一個虛函數，子類別一定要覆寫它嗎？沒有這個強制規定——不覆寫的話，vtable 裡就沿用父類別的版本。但如果是純虛函數（= 0）就不一樣，子類別一定要實作，否則子類別也是抽象類別、不能建立物件。老師以 QuantLib 為例：Instrument 裡唯一的純虛函數是判斷是否到期的 isExpired()，意思是任何繼承它的金融商品，都一定要有自己版本的「是否到期」判斷方法。老師說：在金融系、財管系學到的各種商品，「哪一個不是金融工具」——所以全部都繼承這個抽象類別。

class Option {

虛解構函數

透過父類別指標 delete 子類別物件時，如果父類別的解構函數不是 virtual，只會執行父類別的解構函數——子類別的解構函數根本不會被呼叫，子類別持有的資源就洩漏了：

C++
#include <iostream>

class BaseBad {
public:
    ~BaseBad() { std::cout << "  BaseBad 解構\n"; }          // 不是 virtual
};
class DerivedBad : public BaseBad {
public:
    DerivedBad() : buf_(new double[1000]) {}
    ~DerivedBad() { delete[] buf_; std::cout << "  DerivedBad 解構，釋放 buffer\n"; }
private:
    double *buf_;
};

class BaseGood {
public:
    virtual ~BaseGood() { std::cout << "  BaseGood 解構\n"; }  // virtual
};
class DerivedGood : public BaseGood {
public:
    ~DerivedGood() override { std::cout << "  DerivedGood 解構\n"; }
};

int main() {
    std::cout << "非虛解構函數：\n";
    BaseBad *p = new DerivedBad;
    delete p;                       // 只執行 BaseBad 的解構：buffer 洩漏（嚴格說是未定義行為）
    std::cout << "虛解構函數：\n";
    BaseGood *q = new DerivedGood;
    delete q;                       // 先子類別、再父類別，正確
    return 0;
}

  BaseBad 解構

  BaseGood 解構
重點規則

任何打算被繼承、會透過父類別指標使用的類別，解構函數都要宣告為 virtual（例如 virtual ~Instrument() = default;）。本章所有的父類別都這樣寫。

老師上課怎麼說老師的提醒

老師說明為什麼父類別的解構函數前面要加 virtual：沒有加的話，透過父類別指標 delete 時，子類別的解構函數根本不會被呼叫，「你的資源管理、記憶體管理一定會出現問題，程式運行一久記憶體就會不夠」。至於要不要再寫成純虛的 = 0，並沒有要求，重點是 virtual 要加。老師也特別指出範例中的 new int[50]（中括號）配置的是 50 個 int 的陣列，解構函數就必須自己寫 delete[]——作業裡也有類似的題目。

類別中含有 virtual double npv() const = 0;，則下列何者正確？

  1. (A)這個類別可以直接建立物件，npv 回傳 0
  2. (B)這個類別是抽象類別，不能建立物件
  3. (C)子類別不能覆寫 npv
  4. (D)= 0 表示 npv 的預設回傳值是 0

Q2

簡答｜中虛解構函數

Instrument *p = new Swap(...); delete p; 若 Instrument 的解構函數不是 virtual，會發生什麼事？

答案

delete 時依指標型態 Instrument* 決定呼叫哪個解構函數，只會執行 Instrument 的解構函數，Swap 的解構函數不會被呼叫，Swap 自己持有的資源（例如動態配置的現金流表）不會被釋放，造成資源洩漏；依標準這是未定義行為。只要把父類別的解構函數宣告為 virtual 就能正確地先解構子類別、再解構父類別。

8.5QuantLib 風格：策略模式與定價引擎

老師講義指出，QuantLib 的整個架構建立在「虛函數＋覆寫」之上：商品（Instrument）只描述合約條件，定價引擎（PricingEngine）負責計算價格，而引擎是可以替換的——同一張債券可以用簡單折現引擎，也可以換成利率模型引擎。把「演算法」抽離成可替換物件的做法，叫策略模式（Strategy Pattern）。

C++
#include <iostream>
#include <memory>
#include <vector>
#include <cmath>

// ---- 殖利率曲線（介面＋兩種實作）----
class YieldCurve {
public:
    virtual double discount(double t) const = 0;
    virtual ~YieldCurve() = default;
};

class FlatCurve : public YieldCurve {
public:
    explicit FlatCurve(double r) : r_(r) {}
    double discount(double t) const override { return std::exp(-r_ * t); }
private:
    double r_;
};

class LinearZeroCurve : public YieldCurve {          // 零利率隨期限線性上升
public:
    LinearZeroCurve(double r0, double slope) : r0_(r0), slope_(slope) {}
    double discount(double t) const override { return std::exp(-(r0_ + slope_ * t) * t); }
private:
    double r0_, slope_;
};

// ---- 定價引擎（策略介面）----
class Bond;
class PricingEngine {
public:
    virtual double calculate(const Bond &bond) const = 0;   // 唯一的策略介面
    virtual ~PricingEngine() = default;
};

// ---- 商品：不自己算價格，交給引擎 ----
class Bond {
public:
    Bond(double face, double coupon, int years) : face_(face), coupon_(coupon), years_(years) {}
    void setPricingEngine(std::shared_ptr<PricingEngine> e) { engine_ = std::move(e); }
    double NPV() const { return engine_->calculate(*this); }
    std::vector<double> cashflows() const {
        std::vector<double> cf(years_, face_ * coupon_);
        cf.back() += face_;
        return cf;
    }
private:
    double face_, coupon_;
    int years_;
    std::shared_ptr<PricingEngine> engine_;
};

// ---- 具體引擎：用曲線折現 ----
class DiscountingBondEngine : public PricingEngine {
public:
    explicit DiscountingBondEngine(std::shared_ptr<YieldCurve> curve) : curve_(std::move(curve)) {}
    double calculate(const Bond &bond) const override {
        std::vector<double> cf = bond.cashflows();
        double npv = 0;
        for (std::size_t i = 0; i < cf.size(); ++i) npv += cf[i] * curve_->discount(i + 1.0);
        return npv;
    }
private:
    std::shared_ptr<YieldCurve> curve_;
};

int main() {
    Bond bond(100, 0.03, 3);

    auto flat = std::make_shared<FlatCurve>(0.025);
    bond.setPricingEngine(std::make_shared<DiscountingBondEngine>(flat));
    std::cout << "平坦曲線 2.5%：NPV = " << bond.NPV() << "\n";

    auto steep = std::make_shared<LinearZeroCurve>(0.015, 0.004);
    bond.setPricingEngine(std::make_shared<DiscountingBondEngine>(steep));   // 換引擎，Bond 不用改
    std::cout << "上升曲線：      NPV = " << bond.NPV() << "\n";
    return 0;
}

平坦曲線 2.5%：NPV = 101.337
上升曲線：      NPV = 100.795
  • Bond 本身不會算價格，它只持有一個 PricingEngine 的智慧指標；NPV() 把工作交給引擎。
  • 引擎依賴的是抽象的 YieldCurve，換成任何一種曲線都可以。
  • 曲線用 shared_ptr：好幾個引擎、好幾張債券可以共用同一條曲線（第 6 章）。
  • 新增定價方法（例如蒙地卡羅引擎）只要再寫一個 PricingEngine 的子類別；Bond 與使用端的程式碼都不用改。這就是 QuantLib 能讓新產品、新模型「直接插上去」的原因。

自編練習題（選擇、填空、預測輸出、找錯、寫程式），不是老師出的題目。寫程式題的參考答案都實際編譯執行過。

Q1

寫程式｜難新增一個引擎

在上面的架構中新增一個 SpreadBondEngine：它持有一條曲線和一個信用利差 s，折現因子用 curve->discount(t) * exp(-s * t)。用平坦 2.5% 曲線加上 150bp 利差計算同一張債券的 NPV。（只需寫出新的類別與 main 中的使用方式；可以把上面的程式整段複製後加上去。）

答案

class SpreadBondEngine : public PricingEngine {
public:
    SpreadBondEngine(std::shared_ptr<YieldCurve> curve, double spread)
        : curve_(std::move(curve)), s_(spread) {}
    double calculate(const Bond &bond) const override {
        std::vector<double> cf = bond.cashflows();
        double npv = 0;
        for (std::size_t i = 0; i < cf.size(); ++i) {
            double t = i + 1.0;
            npv += cf[i] * curve_->discount(t) * std::exp(-s_ * t);
        }
        return npv;
    }
private:
    std::shared_ptr<YieldCurve> curve_;
    double s_;
};

8.6friend：開放給特定的朋友

友函數（friend function）是被類別「列入白名單」、可以存取它 private 與 protected 成員的非成員函數；友類別（friend class）則是整個類別都被授權：

C++
#include <iostream>

class Account {
public:
    explicit Account(double b) : balance_(b) {}
    friend void audit(const Account &a);             // 友函數：不是成員，但能看 private
    friend class RiskManager;                        // 友類別：RiskManager 的所有成員函數都能看
private:
    double balance_;
    double limit_ = 50000;
};

void audit(const Account &a) {                       // 一般的全域函數，沒有 Account::
    std::cout << "稽核：餘額 " << a.balance_ << "，額度 " << a.limit_ << "\n";
}

class RiskManager {
public:
    void tighten(Account &a, double ratio) { a.limit_ *= ratio; }   // 直接改 private 成員
};

int main() {
    Account acc(120000);
    audit(acc);
    RiskManager rm;
    rm.tighten(acc, 0.5);
    audit(acc);
    return 0;
}

  • friend 宣告寫在類別內，但友函數不是成員函數：沒有 this、不用物件呼叫、實作時不寫 類別名::。
  • friend 只是編譯期的權限設定，不改變記憶體配置，執行時與一般函數完全一樣。
  • friend 關係是單向的（A 把 B 當朋友，不代表 B 把 A 當朋友），也不會被繼承。
  • 常見用途：需要存取 private 的 operator<<；兩個緊密合作的類別（老師提到 QuantLib 的 Handle 與它觀察的物件、Instrument 把計算結果交給引擎寫入）。
  • 老師的提醒：friend 是強大的武器，但濫用會破壞封裝，能用公開介面解決就不要用 friend。
老師上課怎麼說白名單

老師的比喻：類別的成員分成外界用得到的 public，以及藏起來的 private、protected；只要類別宣告某個函數或類別是「好朋友」，它就拿到一張許可證，可以存取這些沒公開的部分——「等同於是白名單的意思」。友函數本身還是一個普通的全域函數，並沒有因此變成類別的成員。

8.7多重繼承與虛擬繼承

多重繼承

C++ 允許一個類別同時繼承多個父類別（Java 不允許，Python 允許）：

C++
#include <iostream>

class Tradable {
public:
    Tradable() { std::cout << "Tradable "; }
    void trade() const { std::cout << "可交易\n"; }
    int id = 1;
};

class Payable {
public:
    Payable() { std::cout << "Payable "; }
    void pay() const { std::cout << "會付息\n"; }
    int id = 2;
};

class CorporateBond : public Tradable, public Payable {   // 繼承兩個父類別
public:
    CorporateBond() { std::cout << "CorporateBond\n"; }
};

int main() {
    CorporateBond b;          // 父類別依「繼承列表的順序」建構
    b.trade();
    b.pay();
    // std::cout << b.id;     // 錯誤：名稱衝突，不知道是哪一個 id
    std::cout << b.Tradable::id << " " << b.Payable::id << "\n";   // 要明確指定
    return 0;
}

  • 父類別的建構順序依繼承列表的順序（Tradable, Payable），和初始化列表怎麼寫無關。
  • 父類別有同名成員時會產生名稱衝突，必須用 父類別::成員 指定。

菱形繼承與虛擬繼承

C++
#include <iostream>

class Counter {
public:
    Counter() { std::cout << "Counter 建構\n"; }
    int count = 0;
};

class BuySide  : virtual public Counter {};      // 虛擬繼承
class SellSide : virtual public Counter {};

class Desk : public BuySide, public SellSide {};   // 菱形：兩條路都通往 Counter

int main() {
    Desk d;                  // Counter 只建構一次
    d.BuySide::count += 3;
    d.SellSide::count += 2;
    std::cout << "count = " << d.count << "（只有一份，可以直接用）\n";
    return 0;
}

Counter 建構
count = 5（只有一份，可以直接用）
  • 菱形繼承：Desk 經由 BuySide 和 SellSide 兩條路繼承 Counter。沒有虛擬繼承時，Desk 裡會有兩份 Counter，d.count 有歧義、Counter 也會建構兩次。
  • 在中間層加上 virtual public（虛擬繼承），最終物件裡就只有一份共用的 Counter。
  • 老師講義強調：菱形繼承不一定是錯誤，要依需求判斷——如果買方、賣方要分別計數，兩份 Counter 才是對的（不要用虛擬繼承）；如果要統計總交易次數，才用虛擬繼承共用一份。標準程式庫的 std::iostream 同時繼承 istream 與 ostream，兩者以虛擬繼承共用 ios_base，是經典案例。
  • 虛擬繼承（決定物件的組成）和虛函數（決定呼叫哪個版本）是兩個不同的概念，只是都用 virtual 這個字。
  • 多重繼承會增加設計複雜度，實務上最常見的安全用法是「繼承一個實作類別＋多個純介面（抽象類別）」。

選擇｜中虛擬繼承

B、C 都繼承 A，D 同時繼承 B 和 C。在 B、C 使用 virtual public A 的目的是？

  1. (A)讓 A 的函數都變成虛函數
  2. (B)讓 B 和 C 可以存取 A 的 private 成員
  3. (C)讓 D 不能建立物件
  4. (D)讓 D 物件中只有一份 A 子物件
答案 (D)

讓 D 物件中只有一份 A 子物件

解析

8.8設計模式：單例（Singleton）

有些東西在整個程式裡只應該有一份：全域設定、評價日期、市場資料管理器。單例模式確保某個類別只有一個實例，並提供統一的存取點。QuantLib 的 Settings::instance().evaluationDate() 就是用它管理「今天是哪一天」——所有商品、曲線都以這個日期為基準計算。

C++
#include <iostream>
#include <string>

class Settings {
public:
    static Settings &instance() {          // 唯一的存取點
        static Settings inst;              // static 區域變數：第一次呼叫時建立，只建立一次
        return inst;
    }
    Settings(const Settings &) = delete;              // 禁止複製
    Settings &operator=(const Settings &) = delete;   // 禁止賦值

    void setEvaluationDate(const std::string &d) { date_ = d; }
    const std::string &evaluationDate() const { return date_; }

private:
    Settings() { std::cout << "（Settings 建立）\n"; }   // 建構函數是 private：外界不能自己建立
    std::string date_ = "2026-01-02";
};

void price_something() {
    const std::string &d = Settings::instance().evaluationDate();
    std::cout << "定價日 = " << d << "\n";
}

int main() {
    price_something();
    Settings::instance().setEvaluationDate("2026-11-13");     // 改一次，全程式都看到
    price_something();
    std::cout << "同一個物件嗎？" << (&Settings::instance() == &Settings::instance()) << "\n";
    // Settings s;                                             // 錯誤：建構函數是 private
    // Settings copy = Settings::instance();                   // 錯誤：複製被 delete
    return 0;
}

（Settings 建立）

同一個物件嗎？1

這個實作把本學期學過的東西組合在一起：

  • private 建構函數：外界無法用 Settings s; 或 new Settings 建立第二個。
  • = delete 複製建構與複製賦值：也無法複製出第二個。
  • static 成員函數 instance()：不需要物件就能呼叫。
  • static 區域變數（第 5 章）：只在第一次呼叫時初始化（延遲初始化），程式結束時自動解構；C++11 起這個初始化也保證執行緒安全。

老師的提醒：單例的「唯一」只在同一個程式（行程）之內；而且它本質上是全域狀態，過度使用會讓程式難以測試，要節制。

Q1

簡答｜中單例的實作

單例模式的實作中，為什麼要把建構函數設為 private，又要把複製建構函數與複製賦值運算子設為 = delete？

答案

建構函數設為 private，外界就不能用 Settings s; 或 new Settings 自己建立物件，只能透過 static 的 instance() 取得唯一的那一個；但即使不能直接建構，若允許複製，仍可以用 Settings s2 = Settings::instance(); 複製出第二個物件，所以要把複製建構與複製賦值都刪除，才能保證整個程式只有一個實例。

8.9本章小結

  • 繼承 class D : public B：子類別沿用父類別、只寫新增的部分；建構先父後子、解構先子後父；用初始化列表呼叫父類別建構函數。
  • 存取等級：public（全部）、protected（自己＋子類別）、private（只有自己）；繼承方式決定父類別成員在子類別的等級，幾乎都用 public。
  • 多型：父類別指標／參考指向子類別物件；virtual 讓呼叫在執行期依實際型態決定（vtable）；子類別覆寫一律加 override；dynamic_cast 安全向下轉型。
  • 遮蔽：同名但不構成覆寫時，子類別會蓋掉父類別所有同名函數；用 using Base::f; 引入。重載（編譯期、同作用域）、覆寫（執行期、虛函數）、遮蔽（名稱查找）是三件事。
  • 純虛函數 = 0 與抽象類別：只定義介面、不能實例化；父類別的解構函數要 virtual。
  • 策略模式：商品持有可替換的定價引擎——QuantLib 架構的核心。
  • friend：授權非成員函數或其他類別存取 private，單向、不繼承，勿濫用。
  • 多重繼承：名稱衝突用 父類別:: 指定；菱形繼承用虛擬繼承共用一份基底，依需求決定。
  • 單例模式：private 建構＋刪除複製＋static instance()（static 區域變數）。
