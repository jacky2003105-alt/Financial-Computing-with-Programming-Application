這是「金融計算程式運用」（陳正暉老師）的 C++ 課程筆記，從完全沒寫過 C++ 的角度重新寫。章節順序照老師的講義一～七與課程總結；每個觀念都附上完整、可以直接編譯執行的程式，下方的「執行結果」是網站實際用 g++ 編譯、執行後貼上的，不是手打的（g++ 是 Linux 上常見的 C++ 編譯器；你的 Mac 用的是 clang++／AppleClang，兩者都照同一份 C++ 標準，這些程式在兩邊結果相同）。故意寫錯的程式則附上編譯器真正的錯誤訊息，讓你習慣讀錯誤訊息。

每一節的寫法固定：先講觀念（用生活或金融的比喻）→ 最小的程式 → 逐行解釋 → 換個寫法或常見錯誤 → 金融應用 → Concept Check。老師上課特別強調的地方用紅框「老師上課強調」、上課的講法整理成紫框「老師上課怎麼說」。

怎麼讀這份筆記

  • 一定要自己打一次程式：按程式碼右上角「複製」可以複製，但建議至少自己打一遍，再改改數字看結果怎麼變。
  • 看執行結果：程式下方灰底的「執行結果」就是螢幕上會看到的東西；黃色是編譯器警告、紅色是編譯錯誤。
  • 測驗模式：頁首選單或首頁的「測驗模式」，選章節、題型與題數隨機出題，交卷後計分，每題都能連回教學處。
  • 畫重點與筆記：在章節頁選取文字，按顏色畫重點或「加筆記」；「我的重點與筆記」頁整理全部內容，可以匯出備份或匯入到另一台裝置。這些紀錄只存在你自己的瀏覽器，別人看不到。
  • 搜尋：頁首「搜尋」或按 /、⌘K（Windows 是 Ctrl K）跨章搜尋，方向鍵選擇、Enter 前往。
  • 本頁大綱、只看不熟、解答：都在頁首；每題右上角可以標「不熟」，解答預設顯示，想先作答就按「隱藏全部解答」。右上角的月亮按鈕切換深色模式。
  • 不用一次全懂：C++ 的很多細節（記憶體、指標、類別）要反覆看才會通，第一次讀先抓「能寫出會動的程式」。

開發環境（最快能開始寫程式的方法）

  • 不想安裝任何東西：先用線上編譯器（例如 Compiler Explorer godbolt.org、OnlineGDB）貼上程式就能跑，適合練習前幾章。
  • Mac：在終端機輸入 xcode-select --install 安裝 Clang 編譯器，再用 VS Code 撰寫；之後裝 Homebrew、CMake（老師的 QuantLib 專案需要）。
  • Windows：安裝 Visual Studio 2022（勾選「使用 C++ 的桌面開發」），或安裝 WSL 後在 Linux 裡用 g++。
  • 終端機編譯一個檔案：g++ -std=c++20 -Wall main.cpp -o main，執行：./main（Windows 是 main.exe）。第 1 章有詳細說明。

名詞小辭典

正文裡加了虛線的名詞，滑過或點一下就會跳出這裡的說明。下面是完整清單，可以直接篩選。

CMakeCMake
產生建構檔的工具：寫一份 CMakeLists.txt，CMake 依系統產生 Makefile 或 Visual Studio 專案，用來一次編譯多個檔案或連結程式庫。 詳見 第 1 章 1.7 →
QuantLibQuantLib
開放原始碼的 C++ 量化金融程式庫，提供利率曲線、債券、選擇權等商品與定價引擎，大量使用類別、多型、模板與設計模式。 詳見 第 1 章 1.1 →
include guardinclude guard
標頭檔開頭的 #ifndef／#define／#endif，讓同一個標頭檔被引入多次時只生效一次。 詳見 第 1 章 1.6 →
前處理preprocessor
編譯前先處理 # 開頭的指令：把 #include 的檔案內容貼進來、展開 #define、處理條件編譯。 詳見 第 1 章 1.6 →
原始檔source file
副檔名 .cpp 的檔案，放程式的實作，是編譯器真正編譯的單位。 詳見 第 1 章 1.3 →
宣告declaration
告訴編譯器「有這個名字、它是什麼型態」，例如 double rate; 或函數的原型。宣告可以有很多次，定義只能一次。 詳見 第 1 章 1.6 →
敘述statement
程式中一個完整的指令，大多以分號 ; 結尾，就像中文句子結尾的句號。也稱語句。 詳見 第 1 章 1.3 →
標準程式庫standard library
C++ 內建、不用另外安裝的工具集合，例如 iostream、vector、string、algorithm，全部放在 std 命名空間。 詳見 第 1 章 →
標頭檔header file
副檔名 .h／.hpp 的檔案，通常只放宣告（有哪些函數、類別），讓其他檔案用 #include 引入。 詳見 第 1 章 1.3 →
編譯compile
把原始碼翻譯成目標檔的步驟；完整流程是前處理 → 編譯 → 連結，最後得到執行檔。 詳見 第 1 章 1.6 →
編譯器compiler
把人寫的 C++ 原始碼翻譯成電腦能執行的機器碼的程式，例如 g++、clang++、MSVC。C++ 要先編譯成執行檔才能跑，不像 R 可以一行一行直接執行。 詳見 第 1 章 1.2 →
連結link
把各個 .cpp 編譯出的目標檔和用到的程式庫接在一起，產生一個執行檔。找不到某個函數的定義時，錯誤會在這一步出現。 詳見 第 1 章 1.6 →
constconst
「不可修改」的標記。const 變數建立後不能改；const 參考可以讀但不能透過它修改；成員函數後面加 const 表示它不會改物件的資料。 詳見 第 2 章 →
constexprconstexpr
要求在「編譯時」就算出結果的常數或函數；值寫死在程式裡，執行時不用再算。 詳見 第 2 章 →
enumenumeration
列舉：把一組有名字的常數定義成一個型態，例如 enum class Side { Buy, Sell };。 詳見 第 2 章 →
nullptrnull pointer
表示「指標沒有指向任何物件」的特殊值。對 nullptr 取值（*p）會讓程式出錯。 詳見 第 2 章 →
unionunion
所有成員共用同一塊記憶體的自訂型態，同一時間只有一個成員有效。 詳見 第 2 章 →
位址address
記憶體每一格的編號。用 & 取得變數的位址，例如 &x。 詳見 第 2 章 2.2 →
初始化initialization
變數建立的同時給它第一個值，例如 int n{3};。沒有初始化的區域變數內容是不確定的。 詳見 第 2 章 2.2 →
參考reference
已經存在的變數的別名，寫成 double& r = x;。透過 r 改值就是改 x；綁定之後不能改綁別的變數。 詳見 第 2 章 2.6 →
型態type
資料的種類，決定一個值占多少記憶體、可以做哪些運算，例如 int、double、bool。C++ 的每個變數都必須先宣告型態。 詳見 第 2 章 2.1 →
字面值literal
直接寫在程式裡的值，例如 42、3.14、"Hello"、true。 詳見 第 2 章 2.4 →
指標pointer
存放「另一個變數的位址」的變數，寫成 double* p = &x;，用 *p 取得或修改它指向的值。可以改指向別處，也可以是 nullptr（不指向任何東西）。 詳見 第 2 章 2.6 →
票息coupon
債券每期支付的利息，等於面額 × 票息率；零息債沒有票息，只在到期時還本。 詳見 第 2 章 →
結構struct
把幾個相關的資料打包成一個新型態，例如把面額、票息率、年期包成 Bond。和 class 幾乎一樣，只差預設的存取權限是 public。 詳見 第 2 章 2.10 →
變數variable
有名字的一塊記憶體，裡面放的值可以改變。 詳見 第 2 章 2.2 →
面額face value
債券到期時償還的本金金額，例如 1000 元；票息也是用面額乘上票息率計算。 詳見 第 2 章 →
lambdalambda expression
寫在程式中間、沒有名字的小函數，例如 [](double x){ return x * x; }，常傳給 sort 等演算法使用。 詳見 第 3 章 3.7 →
vectorstd::vector
標準程式庫的「可變長度陣列」，會自動管理記憶體，可以用 push_back() 加元素、size() 取長度。實務上幾乎都用它取代原始陣列。 詳見 第 3 章 →
容器container
用來裝一堆同型態物件的標準程式庫型態，例如 vector、map、list。 詳見 第 3 章 3.5 →
迭代器iterator
指向容器中某個元素的「游標」，用 begin()、end() 取得，可以 ++ 移到下一個；標準演算法（sort、find）都靠它運作。 詳見 第 3 章 →
陣列array
固定長度、連續排列的一串同型態資料，例如 double r[5];。長度在編譯時就決定，不能改變。 詳見 第 3 章 →
IRRinternal rate of return
內部報酬率：使一串現金流淨現值等於 0 的折現率；沒有公式解，要用迴圈逐步逼近。 詳見 第 4 章 →
例外exception
程式執行時遇到無法正常處理的狀況（例如輸入不合法）時「丟出」的錯誤物件，用 try／catch 接住處理，沒接住程式就會結束。 詳見 第 4 章 →
殖利率yield
使「未來現金流的折現值總和」等於債券價格的報酬率，可以想成持有到期的年化報酬。殖利率越高，價格越低。 詳見 第 4 章 →
表達式expression
會算出一個結果的程式片段，例如 price * shares。 詳見 第 4 章 →
運算子operator
運算用的符號，例如 + - * / == &&。 詳見 第 4 章 4.1 →
NPVnet present value
淨現值：把所有未來現金流折現到今天再加總（有期初投入時再減掉），用來評價債券或投資計畫。 詳見 第 5 章 →
inlineinline
建議編譯器把函數本體直接展開在呼叫處；也讓函數可以定義在標頭檔而不會重複定義。 詳見 第 5 章 →
作用域scope
一個名字「看得到」的範圍，通常是一對大括號 { }。離開作用域，裡面的區域變數就被銷毀。 詳見 第 5 章 →
傳值pass by value
呼叫函數時把引數「複製一份」給參數，函數內修改不影響外面的變數。 詳見 第 5 章 5.2 →
傳參考pass by reference
參數宣告成參考（例如 double& x），函數拿到的是原本的變數本身，修改會影響外面；加 const 則只讀不改、又省去複製。 詳見 第 5 章 5.2 →
函數function
有名字、可以重複呼叫的一段程式：接收參數、做事、回傳結果。C++ 程式從 main 函數開始執行。 詳見 第 5 章 →
參數parameter
函數定義時括號裡的變數，用來接收呼叫時傳進來的值（呼叫時實際給的值叫引數）。 詳見 第 5 章 →
折現discounting
把未來的錢換算成今天的價值：t 年後的 1 元，今天值 1 ÷ (1 + y)^t 元，這個倍數叫折現因子。 詳見 第 5 章 →
生命週期lifetime
物件從建立到被銷毀的這段時間。區域變數活到離開它的作用域為止；用 new 建立的物件活到被 delete 為止。 詳見 第 5 章 5.9 →
重載overload
同一個作用域裡有好幾個同名函數，但參數的個數或型態不同，編譯器依呼叫時的引數選出最適合的版本。 詳見 第 5 章 5.6 →
命名空間namespace
替名稱分組的「姓氏」，避免不同程式庫的同名函數互相衝突。標準程式庫的東西都在 std 裡，所以寫成 std::cout。 詳見 第 6 章 →
堆疊stack
存放區域變數的記憶體區域，進入函數時自動配置、離開時自動釋放，速度快但空間有限。 詳見 第 6 章 6.3 →
堆積heap
用 new 動態配置的記憶體區域，大小可以在執行時決定，但必須自己 delete 釋放（或交給智慧指標）。 詳見 第 6 章 6.3 →
懸空指標dangling pointer
指向「已經被釋放或已經不存在的物件」的指標。透過它讀寫是未定義行為。 詳見 第 6 章 →
智慧指標smart pointer
會自動 delete 的指標類別：unique_ptr（獨占擁有）、shared_ptr（共同擁有，最後一個用完才釋放）。現代 C++ 用它取代手動 new／delete。 詳見 第 6 章 →
未定義行為undefined behavior
C++ 標準沒有規定結果的操作，例如越界存取、重複釋放、對懸空指標取值。程式可能看起來正常、可能當機、也可能在別台電腦結果不同，不能依賴任何結果。 詳見 第 6 章 →
記憶體洩漏memory leak
用 new 配置的記憶體沒有 delete，程式結束前都拿不回來；長時間執行的程式會越用越多記憶體。 詳見 第 6 章 →
RAIIResource Acquisition Is Initialization
「取得資源就是初始化」：在建構函數取得資源、在解構函數釋放，靠物件的生命週期自動管理資源，不怕忘記釋放。 詳見 第 7 章 7.7 →
explicitexplicit
寫在建構函數前，禁止編譯器拿它做「自動型態轉換」，必須明確寫出建構的動作。 詳見 第 7 章 7.9 →
mutablemutable
寫在成員變數前：即使在 const 成員函數裡也能修改它（常用於快取）。寫在 lambda 後：允許修改以傳值方式捕捉進來的變數副本。 詳見 第 7 章 →
thisthis pointer
每個成員函數裡隱藏的指標，指向「目前呼叫這個函數的物件」。 詳見 第 7 章 7.9 →
三法則rule of three
類別若自己寫了解構函數、複製建構函數、複製賦值運算子其中一個（通常因為管理原始指標），三個通常都要自己寫。 詳見 第 7 章 7.7 →
初始化列表member initializer list
建構函數參數後面冒號開始的部分，例如 Bond(double f) : face_(f) {}，在函數本體執行前就把成員設好；呼叫父類別建構函數也寫在這裡。 詳見 第 7 章 7.9 →
單例Singleton
一種設計模式：讓某個類別在整個程式裡只能有一個物件，並提供取得它的統一入口。 詳見 第 7 章 7.5 →
多型polymorphism
同一個呼叫（例如 bond.payment(t)）依物件實際的型態做出不同的事。C++ 透過虛函數與父類別的指標或參考實現。 詳見 第 7 章 7.1 →
存取權限access specifier
public（外面都能用）、private（只有類別自己能用）、protected（自己和子類別能用）三種，寫在類別裡決定成員給誰用。 詳見 第 7 章 →
實例化instantiation
依照類別或模板產生實際的東西：類別實例化得到物件；模板實例化得到 vector<double> 這種具體型態或函數。 詳見 第 7 章 7.1 →
封裝encapsulation
把資料設成 private，只開放經過檢查的 public 函數給外界使用，讓物件的資料不會被亂改。 詳見 第 7 章 →
建構函數constructor
和類別同名、沒有回傳型態的特殊函數，在物件建立時自動執行，負責設定初始值與檢查參數。 詳見 第 7 章 →
成員函數member function
定義在類別裡的函數，透過物件呼叫，例如 b.price()，可以直接使用物件自己的成員變數。 詳見 第 7 章 →
成員變數member variable
寫在類別裡的變數，每個物件各有一份，例如每張債券各自的面額。習慣上 private 的成員變數名稱後面加底線，例如 face_。 詳見 第 7 章 →
模板template
把型態當成參數的程式，例如 template<typename T> T maxOf(T a, T b)，同一份程式可以用在 int、double 或自訂類別。 詳見 第 7 章 7.1 →
深複製deep copy
複製物件時連指標指向的資料也另外配置一份，兩個物件各自擁有自己的資料、互不影響。 詳見 第 7 章 →
淺複製shallow copy
複製物件時只複製指標的值（位址），兩個物件共用同一塊資料；編譯器預設的複製就是逐一複製成員。 詳見 第 7 章 →
物件object
依照類別這張藍圖建立出來的實體，例如 Bond b(1000, 0.05); 中的 b。同一個類別可以建立很多個彼此獨立的物件。 詳見 第 7 章 →
繼承inheritance
子類別（衍生類別）沿用父類別（基底類別）的成員，再加上或修改自己的部分，例如 FixedRateBond 繼承 Bond。 詳見 第 7 章 7.1 →
複製建構函數copy constructor
用一個既有的物件建立新物件時執行的建構函數，例如 RateCurve b = a;。沒寫時編譯器會自動產生逐一複製成員的版本。 詳見 第 7 章 7.7 →
複製賦值運算子copy assignment operator
兩個都已經存在的物件之間寫 b = a; 時執行的函數 operator=，要處理舊資料的釋放與自我賦值。 詳見 第 7 章 7.7 →
解構函數destructor
名稱是 ~類別名 的特殊函數，在物件被銷毀時自動執行，負責釋放物件擁有的資源（例如 delete 動態配置的記憶體）。 詳見 第 7 章 →
運算子重載operator overloading
替自己的類別定義 +、==、<< 等運算子的意義，讓物件可以像內建型態一樣寫成 a + b。 詳見 第 7 章 7.6 →
重複釋放double free
對同一塊已經 delete 過的記憶體再 delete 一次，屬於未定義行為；淺複製的兩個物件消失時就會發生。 詳見 第 7 章 →
類別class
使用者自己定義的型態，把資料（成員變數）和操作資料的函數（成員函數）包在一起，例如 Bond 類別記得面額，也會算自己的價格。 詳見 第 7 章 →
dynamic_castdynamic_cast
在執行時檢查物件實際型態的安全轉型，例如把 Bond* 轉成 FixedRateBond*；轉不過去時指標版本回傳 nullptr。 詳見 第 8 章 →
vtablevirtual table
編譯器替每個有虛函數的類別建立的「函數位址表」；每個物件藏有一個指向它的 vptr，虛函數呼叫就是查這張表。 詳見 第 8 章 →
動態型別dynamic type
物件「實際上」是什麼型態，在執行時才確定；相對的靜態型別是編譯器從宣告看到的型態。Bond* p = new FixedRateBond; 中 p 的靜態型別是 Bond*、指向物件的動態型別是 FixedRateBond。 詳見 第 8 章 →
名稱查找name lookup
編譯器遇到一個名字時，從目前的作用域（例如子類別）往外找它的宣告，找到就停；遮蔽就是這個「找到就停」造成的。 詳見 第 8 章 8.3 →
基底類別base class
就是父類別：被繼承的那個類別。 詳見 第 8 章 →
多重繼承multiple inheritance
一個子類別同時繼承兩個以上的父類別，寫成 class C : public A, public B。容易造成名稱衝突，實務上少用。 詳見 第 8 章 →
子類別child class
繼承別的類別的類別，也叫衍生類別（derived class）。它自動擁有父類別的 public 成員，再加上或改寫自己的部分；子類別物件「是一種」父類別物件。 詳見 第 8 章 →
抽象類別abstract class
至少有一個純虛函數（= 0）的類別，只能當作介面被繼承，不能直接建立物件。 詳見 第 8 章 →
父類別parent class
被別的類別繼承的類別，也叫基底類別（base class）。例如 FixedRateBond 繼承 Bond，Bond 就是父類別，負責大家共同的部分（面額、年期）。 詳見 第 8 章 →
物件切割object slicing
把子類別物件「按值」複製成父類別物件時，子類別特有的部分被切掉，之後就只剩父類別的行為。 詳見 第 8 章 →
純虛函數pure virtual function
寫成 virtual double f() const = 0; 的虛函數：父類別只規定「一定要有這個函數」，不提供做法，子類別必須覆寫。有純虛函數的類別是抽象類別。 詳見 第 8 章 →
虛函數virtual function
前面加 virtual 的成員函數。透過父類別的指標或參考呼叫時，會在執行時依物件實際的型態，呼叫子類別覆寫的版本。 詳見 第 8 章 →
虛解構函數virtual destructor
加了 virtual 的解構函數。用父類別指標 delete 子類別物件時，才會先執行子類別、再執行父類別的解構函數；會被繼承的類別都應該有。 詳見 第 8 章 →
衍生類別derived class
就是子類別：繼承別人的那個類別。 詳見 第 8 章 →
覆寫override
子類別提供一個和父類別虛函數簽名完全相同的版本，取代父類別的實作；建議加上 override 讓編譯器檢查。 詳見 第 8 章 →
設計模式design pattern
反覆出現的設計問題的標準解法，例如策略模式（可替換的演算法）、單例模式、觀察者模式。 詳見 第 8 章 →
遮蔽name hiding
子類別宣告了和父類別同名的函數時，父類別所有同名函數都被「遮住」，透過子類別呼叫時找不到它們，可用 using 解除。 詳見 第 8 章 →
重載決議overload resolution
同名的函數有好幾個時，編譯器依呼叫時給的引數個數與型別，挑出最合適的那一個。 詳見 第 8 章 8.3 →
零息債zero-coupon bond
期間不付利息、只在到期日支付面額的債券，價格就是面額的折現值。 詳見 第 8 章 →
靜態型別static type
編譯器從宣告看到的型別，例如 Bond* p 的靜態型別是 Bond*；一般函數依它決定呼叫哪個版本，名稱查找也從它開始。 詳見 第 8 章 →
typenametypename
模板裡宣告型態參數（template <typename T>），或告訴編譯器某個名稱是型態。 詳見 第 9 章 9.8 →
Black-ScholesBlack-Scholes model
歐式選擇權的定價公式：用股價、履約價、到期時間、無風險利率與波動度算出買權、賣權價格。 詳見 第 10 章 →
觀察者模式Observer pattern
一種設計模式：資料變動時自動通知所有關心它的物件，例如利率曲線變了，用它定價的商品就知道要重算。 詳見 第 10 章 →
AddressSanitizerAddressSanitizer
編譯時加上 -fsanitize=address 的記憶體錯誤偵測工具，執行時會抓出越界存取、重複釋放、使用已釋放記憶體等問題。 詳見 hw01 →
NaNnot a number
浮點數的「不是數字」，例如 0.0 / 0.0；任何和 NaN 的比較都是 false，所以要用 std::isnan 或 std::isfinite 檢查。 詳見 hw01 →
